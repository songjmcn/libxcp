## 2. 修复项分解

### 15-A 静默错值止血（**无 liba2l ABI 变化**，最高优先）

**F1 · A2L 侧 FIRST_PID 透传并生成 PID 路由**（→ L1）
- 落点：`a2l_dto_map.cpp::ConvertDaqList`（`layout.first_pid = dto.first_pid`）；`a2l_bridge.cpp::CreateDaqLayout()` 在 `first_pid` 有值时按 `first_pid + odt_index` 生成 `snapshot.routes`（docs L2225），并把 `source` 仍标 `A2lPredefined`。
- 同步改注释：`daq_layout.hpp::DaqListLayout::first_pid` 现在写的是「A2L 侧不在此列」，与本项结论相反，必须一并改，否则注释与实现互相打脸。
- **为什么这个缺陷一直没被发现（实测，写进计划以防再犯）**：四个含 DAQ 的样本里，只有 `golden_mask` 的 `FIRST_PID(4)` 与列表号 `(2)` 不同；`golden_basic`(1/1)、`golden_dynamic`(3/1，但走 DYNAMIC 拒绝分支不解码)、`golden_xcpplus`(5/1，该用例只测优先级与冲突不做 DTO 解码) 都不构成反例。而唯一能暴露它的 `golden_mask` 两条用例**恰好喂的是列表号 0x02** —— 即测试与实现用了同一个错误口径，互相验证通过。`A2lSmoke` 也喂 `kEpPid=1`（`a2l_smoke_test.cpp:74` 注释还写着「EPK == DAQ_LIST number」），同样因 basic 两值相等而通过。
- 影响面（已逐个核实：`CreateDaqLayout()` 共 7 处调用点）：
  | 调用点 | 样本（number / first_pid） | 现喂 PID | 修复后动作 |
  |---|---|---|---|
  | `a2l_golden_test.cpp:406` `BitMaskAndDaqBitOffsetAreIndependent` | mask（2 / **4**） | `0x02` | **改 `0x04`**（净荷不变） |
  | `a2l_golden_test.cpp:1184` `StaticPredefinedDaqDecode` | mask（2 / **4**） | `0x02` | **改 `0x04`** |
  | `a2l_golden_test.cpp:1102` `DtoEnvelopeMatrix` | basic（1 / 1） | `1`，注释写「EPK」 | 值不变，**注释口径改「FIRST_PID + 相对 ODT 号」** |
  | `a2l_smoke_test.cpp:312` Gate6 | basic（1 / 1） | `kEpPid=1` | 值不变，**`a2l_smoke_test.cpp:74` 注释同改** |
  | `:1062` `StructureMetadataOnly`、`:1212` `DynamicDaqRejectedExplicitly`、`:1319` 异步用例 | — | 不断言解码结果 | 不受影响 |
- **必须新增的回归锁**（这条是 F1 的真正价值）：`A2lGoldenTest.A2lFirstPidRoutesInsteadOfListNumber` —— 在 `golden_mask` 上喂 `0x02` 必须 `InvalidLayout/NotFound`，喂 `0x04` 才成功；即"列表号巧合撞上别人 PID"这条静默路径被钉死。
- 待决策 **D1**：A2L 声明了 FIRST_PID 时是否**只**认路由（我推荐：是）；未声明时保留 `EPK==列表号` 回退并在 `Error.message` 里写明"按列表号回退"（我推荐：保留但标注，避免既有 A2L 全量失效）。

**F2 · `DecodedDtoSample` 增有效性标记**（→ L2）
- 落点：`daq_layout.hpp::DecodedDtoSample` 增 `bool physical_valid{false}`；`daq_layout_impl.cpp` 换算成功路径置位。
- 消费侧（示例/测试）：断言从 `std::get<int64_t>(v)` 改为「先判 `physical_valid` 再取值」。
- 待决策 **D2**：加 `bool` 标记（推荐，破坏性最小）vs 把字段换成 `std::optional<PhysicalValue>`（语义最干净，但要改所有消费点与 §4.4 草案块）。

**F3 · 位偏归一收回桥接层**（→ L3）
- 落点：`BuildSnapshotFromLedger` / `BuildSnapshotFromEcuReadback` 内部把 `0xFF`（及 `> 单元素位宽` 的非法值）归一为桥接口径，调用方不再需要知道两套约定；`DaqLedgerEntryView::bit_offset` 注释同步改为「允许直接透传 XCP 原值，桥接层负责归一」。
- 与 F2 联动：归一后若仍是有偏位元素，则 `physical_valid=false` + raw 保留（不猜），语义闭环。
- 回归：`xcp_daq_test` 与 E2E 里删掉手工归一逻辑，改为透传 `0xFF`，断言物理值仍正确（这条改动能直接证明"陷阱被拆掉"）。

**F4 · 让陈旧快照可被识破**（→ L4）
- 落点：`IDaqLayout` 增只读 `[[nodiscard]] std::uint32_t Generation() const noexcept;`，实现在 `daq_layout_impl.cpp`（直接回 `m_snapshot_.generation`）；`Decode` **不**内部比对（避免改签名与既有 4 条 DAQ 用例的期望）。
- 配套：E2E/示例侧加一条断言形态「取布局时记代际 → CLEAR/重配后再取一次 → 二者不等则必须重建解码器」，把软守卫变成调用方一行可写、可测的硬检查。
- 待决策 **D3**：① 只加 `Generation()`（**推荐**，零破坏）；② `Decode` 增"当前代际"参数并在内部拒配（更硬，但改公开签名 + 既有解码用例全改）。
- 说明：桥接层不持有 ECU 句柄，无法自知"现在的代际"，所以 ①是能力上限内的最强形态；②需把代际来源上移到调用方，属接口风格决策。

### 15-C 能力门与自检（核心侧，无 ABI）

**F7 · 三处前置校验**（→ L7）
- **需新增接口（决策 D7）**：`protocol_types.hpp` 目前只有 `DaqListPropertyBit`（GET_DAQ_LIST_INFO 的 DAQ_LIST_PROPERTIES），**没有** GET_DAQ_PROCESSOR_INFO 的 DAQ_PROPERTIES 位定义（grep 实测 `DAQ_CONFIG_TYPE|DaqProcessorProperty` 0 命中）。要落地"动态 ECU 早失败"必须补：
  `enum class DaqProcessorPropertyBit { kConfigType=0x01, kPrescaler=0x02, kResume=0x04, kBitStim=0x08, kTimestamp=0x10, kNoPid=0x20, kOverloadIndicator=0xC0 }` + `HasDaqProcessorProperty()` constexpr —— 位值交叉参考 `thirdparty/XCPlite/src/xcp.h:353-359`（沿用批次14 确立的"偏移/位值以 XCPlite 为只读参考"纪律，已在 `command_codec.hpp` 顶部对照表注明）。
- 动态 ECU 早失败：`DAQ_PROPERTY_CONFIG_TYPE`（bit0）为 1 → 动态型 → `ConfigureDaqList` 在任何命令发出前抛 `UnsupportedFeature`（B-5 语义从"链路中段报错"前移）。**代际/取证数据来源问题（决策 D8）**：XcpMaster 当前不缓存 `GET_DAQ_PROCESSOR_INFO` 结果，故三种做法可选 ——
  ① **推荐**：首次配置时由 `ConfigureDaqList` 内部查一次并缓存进 Session（Slave 回 CMD_UNKNOWN 则缓存"未知"并维持现行为，不猜）；代价是配置路径多发 1 条 Optional 命令；
  ② 要求调用方先自行 `QueryDaqProcessorInfo()` 再把结果作为入参传入（零额外流量，但把责任推给调用方）；
  ③ 不做（保持 L7 现状）。
- `pid_off` fail-fast：`DaqListSpec.pid_off==true` 而解码侧必拒 → 配置阶段抛 `InvalidArgument`；若 D8 取 ①，可同时校验 ECU 是否声明 `DAQ_PROPERTY_NO_PID`（0x20）作为附加证据。
- MAX_DTO 预检：`Σ(entry.size × AG) + header_bytes ≤ MAX_DTO` → 超限抛 `InvalidArgument`，消息里带上列表号、算式与实算值。
  **防错提示（本批真实踩过）**：`DaqEntrySpec::size` 是**元素数（AG 单位）**，不是字节数；AG=Word 时 `Σ(size)+header` 这种写法会漏乘 AG，把 2 字节 entry 算成 1 字节而放过超限配置。

**F8 · "能力未取证"显式化**（→ L8）
- 落点：`RuntimeXcpParams` 三项 DAQ 字段全为 `nullopt` 时，`CompareWithRuntime` 产出一条 **Warning**「DAQ 布局权威未经运行时取证（未实现 GET_DAQ_PROCESSOR_INFO）」，而不是静默零差异；配合 F6 的告警通道可在 UI 常驻提示。

### 15-D 工程债与测试自洽（只动 tests）

**F9 · Slave 的 RESOURCE 位与 DAQ 开关联动**（→ L9）
- 改动：DAQ 关闭时 CONNECT 的 `RESOURCE` 清掉 DAQ 位（`0x15 → 0x11`）。
- 已知代价（批次14 分析过，写清避免重踩）：E2E `RuntimeConsistencyMatchesA2l` 会因此多出 `DAQ_SUPPORT` 一条差异 → 该用例的 `diff.size()==2` 与 `rt.has_daq` 取值需同步调整。**方案**：让该用例在建桥后显式 `SetDaqSimulationEnabled(true)`，保持它原本"验证一致性"的意图不变。

**F10 · 门禁可信度**（→ L12）
- T9 预算由绝对值改为「绝对值 + 倍率」双条件（如 `> 3× 参考中位数 或 > 3000 ms` 才失败），并把实测值写进 ctest 输出；换机不再假失败。
- `ParseLargeFileUnderBudget` 的 SKIP 分支改为**显式要求 fixture**：给该 ctest 条目加 `FIXTURES_REQUIRED A2lPerf`（性能文件由 `a2l_perf_gen` 产出），缺装配即配置期报错而不是运行时静默 SKIP——这样"全绿"的含义在任何调用方式下都一致。
  实施时若发现 `FIXTURES_REQUIRED` 与现有 `A2lGolden` 夹具链冲突（同一条目挂多个夹具），退路是把该用例从 `A2lGolden` 拆成独立可执行文件；两种做法都在记录里写明选了哪个及原因。
