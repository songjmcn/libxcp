# 传输帧布局自动协商与版本参数降级 —— 实施计划

- 提出背景：用户希望「TCP/UDP transport 层自己解决版本问题，`xcp_master` 不再要求用户传版本参数」
- 本轮范围：**先出计划，不改代码**（AGENTS.md：方案获批前禁止实现）
- 上报文件：`code-plan/传输帧布局自动协商_实施计划.md`

## 0. 结论速览

需求拆成三件互相独立的事，可行性不同：

| # | 要自动确定的东西 | 现状 | 本次方案 | 阶段 |
|---|---|---|---|---|
| 1 | UDP 帧 Tail / 对齐 | 必填 `packet_alignment`，`Unknown` 直接拒绝 | **改由数据报边界推导**，发送侧不再补白 | **P1** |
| 2 | TL / PL 版本号 | 已自动（CONNECT + GET_VERSION，`autodetect_version` 默认 true） | CLI 参数**降级为可选 override**；A2L 的 PL 版本参与裁决 | **P2** |
| 3 | TCP 帧布局 Profile + 对齐 | 必填 `wire_profile` + `packet_alignment` | **连接级候选试连**（显式 `--tcp-profile auto`） | **P3** |

用户已裁决（m05767）：

1. TCP 自动协商**必须显式开启**（`--tcp-profile auto`），不得默认启用；
2. 候选顺序固定 `{V14,8} → {V15,8} → {V15,16} → {V15,32}`；
3. 接受最坏 4 次连接 / 约 8 s，**不接受**“最多 2 次”的保守上限；
4. 同意收窄 `tcp_wire_profile.hpp` 里“明令禁止自动探测”的措辞（详见 §7）。

## 1. 现状核证（全部为工具实测，非记忆）

### 1.1 为什么 TCP 是唯一的“鸡生蛋”

- 帧布局只有两份实现，且**编码时刻就分叉**：`src/tcp_transport.cpp:598-607`
  - `AsamV14` → `EncodeEthernetFrameUnpadded()`：严格 `[LEN][CTR][Packet]`；
  - `AsamV15` → `EncodeEthernetFrameAligned(...)`：Tail 补在 **LEN 之外**。
- `wire_profile == Unknown` 时 `Open()` 直接拒绝（`src/tcp_transport.cpp:139-142`），**没有默认回退**。
- 解码侧 Tail 长度由 `(align - (4+LEN) % align) % align` 推出（`src/tcp_stream_decoder.cpp:181-219`，公式定义在 `include/libxcp/protocol_types.hpp:995-1004`，取值域 0..3）。判错不是“报错”而是**错位**：
  - V14 流按 V15 读 → 吃掉下一帧 Header 的前 1..3 字节；
  - V15 流按 V14 读 → 把 FILL 当下一帧的 LEN。
- 8-bit 对齐下两种布局**字节完全相同**（都是 `4+LEN`），无法从字节区分。
- Profile 还影响 CTR 严格性：`src/tcp_transport.cpp:817` —— `AsamV15` 缺号即断链，`AsamV14` 仅告警。

### 1.2 为什么 UDP 可以不需要对齐参数

- 解码现状：`src/udp_transport.cpp:829` 调 `DecodeUdpDatagramAligned(view, m_config_.packet_alignment)`；该函数要求 Tail 长度**恰等于**由 alignment 算出的值，否则整体拒绝（拒绝清单见 `include/libxcp/ethernet_header_codec.hpp:176-186`：“Header + LEN + Tail 超出 Datagram 剩余长度（截断）”、“跳过 Tail 后仍有无法构成完整 Frame 的残尾”）。
- 但 **UDP 一个数据报就是一个承载单元，边界即 Frame 边界**，因此 `tail = datagram.size() - 4 - LEN` 可直接观测，只需落在 0..3。alignment 对 UDP 接收**是冗余信息**。
- 发送侧：TL V1.5 §4.3.2.1「单个 XCP 消息独占 Frame 时 Tail 是可选的」→ 主站 CRO 恒不补白，任何 alignment 的对端都能接受。现状是 `src/udp_transport.cpp:596-598` 按 alignment 主动补白，属于**不必要的不兼容源**。

### 1.3 版本号本来就已经自动

- CONNECT 响应带 PL/TL **主版本**：`src/response_parser.cpp:219-220`。
- GET_VERSION（`0xC0 0x00`）带 PL 主+次、TL 主+次：`include/libxcp/response_parser.hpp:209-230`。
- `XcpMasterOptions::autodetect_version` **默认 true**（`include/libxcp/xcp_master.hpp:151-154`），CONNECT 后自动探测。
- 裁决优先级 GET_VERSION > 配置 > A2L > CONNECT 主版本：`src/version_resolver.cpp:43-63`。
- 因此 `--transport-version` / `--protocol-version`（`tools/xcp_master/main.cpp:286`、`:293`）当前只承担两个作用：产出**冲突告警**、给能力裁决一个“配置”来源（优先级低于运行时证据）。
- 唯一精度缺口：对端不实现 GET_VERSION 时（XCPlite V1.2 / PL 1.2 就是），只有主版本 → `conservative` 按 `Major.0` 取能力交集（`src/version_resolver.cpp:130-148`），可能低估能力。补救是把 A2L `PROTOCOL_LAYER` 也喂进裁决（`VersionResolver::Inputs::a2l_protocol_version` 已存在，CLI 目前只喂了 `transport_version`）。

## 2. 目标与非目标

### 2.1 目标

- **G1**：UDP 路径不再需要用户提供 `packet_alignment`；主站发送不补白，接收按数据报边界容忍 0..3 字节 FILL。
- **G2**：`--protocol-version` / `--transport-version` 变为纯可选 override；不传也能连接，且 A2L 的 PL 版本参与裁决以降低保守低估。
- **G3**：`--tcp-profile auto` 时自动确定 Profile + 对齐；成功后把“选中的候选 + 尝试次数 + 依据”打印到启动摘要。
- **G4**：三种能力都**显式开启且可关闭**，关闭后行为与今天完全一致（逐字节等价）。
- **G5**：全部新增逻辑可单测（不依赖真实端口），并保持现有 992 项回归全绿。

### 2.2 非目标

- 不在**同一条 TCP 连接内**做字节嗅探、不中途切换 Profile（见 §7）。
- 不自动推断 A2L 是否存在、不改变 A2L 端点选择规则（多实例 fail-closed 等保持原样）。
- 不改 `thirdparty/`。
- 不做 UDP 侧“多候选试连”（UDP 不需要，见 §4）。
- 不改变 DAQ/标定/编程等上层语义。

## 4. P1：UDP 边界推导

### 4.1 设计

新增纯函数入口（保留旧函数不动，避免破坏既有调用方与测试）：

```cpp
/// @brief 以「承载单元边界」为准解码 UDP 数据报（不依赖 alignment）
/// @param datagram 完整 UDP Payload
/// @param max_tail 允许的最大 Tail 字节数（0..3，默认 3）
/// @return 帧视图；畸形返回 nullopt
[[nodiscard]] std::optional<std::vector<EthernetFrameView>>
DecodeEthernetDatagramByBoundary(BytesView datagram,
                                 std::uint8_t max_tail = 3) noexcept;
```

规则：
1. 逐帧读 Header → `LEN`；
2. `tail = datagram.size() - cursor - 4 - LEN`：仅当**这是本数据报最后一帧**时才允许 `tail ∈ [0, max_tail]`（中间帧 Tail 必须为 0，因为主站/从站串联多帧时中间帧必须对齐——若实现需要支持中间帧 Tail，则按 `alignment` 未知时保守要求 `tail ∈ [0,3]` 且 `LEN>0`，见 §4.4 决策）；
3. `LEN == 0`、剩余字节不足、尾部残尾 `> max_tail` → 整体 `nullopt`（保持“数据报原子交付”政策）。

发送侧：`UdpTransport` 改调 `EncodeUdpFrameAligned(packet, ctr, PacketAlignment::Bit8)` 等价路径（即 `EncodeEthernetFrameUnpadded` 语义），**永不补白**；`packet_alignment` 从“必需”改为“可选一致性校验”。

### 4.2 `UdpTransportConfig` 语义变更

| 字段 | 改前 | 改后 |
|---|---|---|
| `packet_alignment` | `Unknown` → `Open()` 失败；同时参与编解码 | 允许 `Unknown`（= 不校验）；给值时仅用于**一致性校验**，不一致时按“宽容接收 + 告警”处理 |

### 4.3 兼容性影响

- 对只支持 8-bit 的从站：字节完全相同。
- 对 16/32-bit 从站：接收由“必须补白”变为“补白可选”，**更宽容**；发送少了 FILL，符合 TL V1.5「单消息 Tail 可选」。
- 既有测试：`tests/udp_header_codec_test.cpp`、`tests/ethernet_header_codec_test.cpp` 直接调用旧函数，不受影响；需检查 `tests/udp_transport_test.cpp` 是否有“按 alignment 断言数据报总长”的用例（实现时逐条核对）。

### 4.4 需要实现期确认的一个细节

多帧串联在同一数据报内时，中间帧的 Tail 是否允许非 0？
- 现状（V15 语义）：中间帧 Tail 由 alignment 推出，必然非 0（当未对齐时）。
- 边界推导无法得知中间帧该有多少 FILL。

**处理**：`DecodeEthernetDatagramByBoundary` 只在 `max_tail>0` 且为最后一帧时容忍 FILL；中间帧要求 Tail=0；若实际对端串联多帧且中间带 FILL，则该数据报整体拒绝并给告警（保持原子性）。是否要放宽为“中间帧按 0..3 逐个试探，取第一个能构成合法后续帧的分支”，留待实现期用真实从站验证后决定（**默认不做试探**，因为试探是嗅探）。

## 6. P3：TCP framing 自动协商（S1 候选试连）

### 6.1 分层：机制在库，裁决由调用方注入

`transport` 只搬字节，无法判断“这段字节是不是合法 CONNECT 响应”。因此：

- **库内提供纯机制**（新文件 `include/libxcp/tcp_framing_negotiation.hpp`）：

```cpp
struct TcpFramingCandidate {
    TcpWireProfile profile = TcpWireProfile::AsamV14;
    PacketAlignment alignment = PacketAlignment::Bit8;
};

/// @brief 固定顺序：{V14,8} → {V15,8} → {V15,16} → {V15,32}
[[nodiscard]] std::vector<TcpFramingCandidate> DefaultFramingCandidates();

/// @brief 一次尝试的结果
struct FramingAttemptOutcome {
    TcpFramingCandidate candidate{};
    bool accepted{false};
    std::string failure_reason;   ///< 被拒原因（供汇总与日志）
    long long elapsed_ms{0};      ///< 该次尝试耗时
};

/// @brief 判定谓词：由调用方实现（内部会做真实 CONNECT）
using FramingAttemptFn =
    std::function<bool(const TcpFramingCandidate&, std::string* out_reason)>;

/// @brief 依序尝试候选，首个被接受者胜出
/// @return 胜出候选；全部失败返回 nullopt，并把每次失败原因写进 out_attempts
[[nodiscard]] std::optional<TcpFramingCandidate> NegotiateTcpFraming(
    const std::vector<TcpFramingCandidate>& candidates,
    const FramingAttemptFn& attempt,
    std::vector<FramingAttemptOutcome>* out_attempts);
```

- **CLI 侧实现谓词**：对每个候选构造 `TcpTransport` + `XcpMaster`，调用 `Connect()`，再做域内校验（见 6.3）。`XcpMaster` 无移动构造（`include/libxcp/xcp_master.hpp:168-183` 只有删除拷贝 + 析构），因此胜出者用 `std::unique_ptr<XcpMaster>` 保存，避免二次连接。

### 6.2 单次尝试状态机

1. 用候选构造 `TcpTransportConfig`（`role=Master`、`remote_host/port`、`packet_alignment=候选`、`wire_profile=候选`）；
2. `TcpTransport::Open(listener)`；
3. `std::make_unique<XcpMaster>(std::move(transport), master_options)`；
4. `master->Connect()` —— 内部已含 `CONNECT → [GET_COMM_MODE_INFO] → GET_STATUS`，本身是**两到三次往返**的天然二次确认；
5. 域内校验（6.3）：任一不满足 → 拒绝该候选，`Disconnect()` 并关闭连接，记录原因；
6. 通过 → 保存 `unique_ptr<XcpMaster>` 与候选，返回成功。

失败清理：`Connect()` 失败时已由内部 `cleanup_on_failure()` 关闭通道并抛 `XcpException`（`src/xcp_master.cpp` Connect 实现），谓词只需捕获异常并写入 `failure_reason`。

### 6.3 域内校验（判定谓词的具体判据）

| 判据 | 依据 | 作用 |
|---|---|---|
| `Connect()` 未抛异常 | 现有语义 | 基本有效性（含“解码器无残留字节”的间接验证：多消费/少消费 Tail 会让下一帧 Header 解析失败） |
| `max_cto ∈ [8, 255]` | XCP 规范 MAX_CTO 域 | 排除把 FILL 当 LEN 造成的随机值 |
| `max_dto ∈ [8, 65535]` | 同上 | 同上 |
| `protocol_layer_version == 1` | XCP 1.x | 排除误读的随机字节 |
| `transport_layer_version == 1` | XCP 1.x | 同上 |
| AG 字段合法 | `ResponseParser` 已校验（`src/response_parser.cpp:200-207`） | 已由解析器保证 |

> 说明：**不额外引入“读取突发长度”判断**（即不做 S2），因此不依赖任何时序假设。

### 6.4 日志与诊断字段

| 时机 | 级别 | 内容 |
|---|---|---|
| 每次尝试开始 | INFO | `TCP framing trial {i}/{n} profile={} alignment={}` |
| 候选被拒 | WARNING | `TCP framing trial {i} rejected: {reason}` |
| 协商成功 | INFO | `TCP framing resolved: profile={} alignment={} after {n} trial(s) in {ms} ms` |
| 全部失败 | ERROR | 逐条列出每个候选的失败原因 + 修复提示（如“对端可能为 XCPlite V1.2，请显式 `--tcp-profile asam-v1.4`”） |

### 6.5 CLI 契约

- `--tcp-profile auto`（新增取值）：必须与 TCP 一起使用；与 `--packet-alignment` **同时给出时直接报错**（auto 会自行枚举对齐，避免“你给的对齐不在候选里”的歧义）；与 `--preset xcplite` **互斥**（preset 已固定 AsamV14）。
- 成功后启动摘要追加：`wire_profile=AsamV14（自动，第 1 次尝试）`、`alignment=8bit（自动）`。
- 失败退出码沿用 3（初始化失败）。

### 6.6 8-bit 歧义的处理

`{V14,8}` 与 `{V15,8}` 字节完全相同，无法区分。按裁决 2 的固定顺序，此时**总是选 `{V14,8}`**：
- 收发字节与 V15/8 一致，功能无损；
- 差异仅在 CTR 严格性（V14 宽松），更不容易把网络抖动误判成失步；
- 若用户需要严格 CTR，可显式 `--tcp-profile asam-v1.5`。

## 7. 文档契约收窄（措辞改动）

### 7.1 `include/libxcp/tcp_wire_profile.hpp` 的文件级注释

把现有「本库**明令禁止**任何自动探测」一段改为：

> 本库**禁止在同一连接内按字节内容猜测并中途切换** Profile：按首帧内容猜测、以超时窥探 Tail、按填充值识别 Tail，都会在边界条件下静默吞掉下一帧 Header，产生极难定位的失步。
>
> 允许的唯一自动化形式是**连接级候选试连**（`--tcp-profile auto`，见 `tcp_framing_negotiation.hpp`）：每个候选用全新连接，失败即断开，绝不污染已有流；候选数量固定、顺序固定、可关闭。Profile 一旦连接建立即不可变。

### 7.2 `code-plan/TCP传输_实施计划_B-T1至B-T5.md` §1.2

追加一段“2026-10-24 收窄”：原文禁止一切自动探测；现区分“同连接内嗅探（仍禁止）”与“连接级候选试连（新增允许，显式开启）”。

### 7.3 `include/libxcp/tcp_transport_config.hpp:88-97` 的 `@note`

“不存在工厂函数 / 禁止自动推断”的措辞同步收窄为“默认必须显式择一；自动模式仅通过 `TcpFramingNegotiation` 的候选试连实现”。

## 9. 测试方案

### 9.1 P1

- `DecodeEthernetDatagramByBoundary`：tail=0/1/2/3 接受；tail=4 拒绝；`LEN=0` 拒绝；残尾拒绝；多帧串联（中间无 FILL）接受。
- `UdpTransport` 发送：alignment=16/32 时 CRO 数据报长度 == `4+LEN`（不补白）。
- 既有 `udp_transport_test` / `udp_header_codec_test` / `ethernet_header_codec_test` 全绿。

### 9.2 P2

- 规则层单测：不给版本参数时 `ResolveTransportSelection` 不报错，`protocol_version/transport_version` 为空。
- 证据链：构造 `Inputs{a2l_protocol_version=1.2, connect_major=1}` → `effective == 1.2`（不是 1.0）、`conservative == false`。
- 互操作：XCPlite V1.2 进程 + 不传版本参数 → 连接成功，摘要显示 PL 来源为 A2L 或 CONNECT。

## 10. 风险与回滚
