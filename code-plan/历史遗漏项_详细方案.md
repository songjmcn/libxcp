## 0 结论速览

| 编号 | 问题 | 现状定性 | 是否改生产代码 | 是否需 ABI 变更 | 建议优先级 | 预估工作量 |
| --- | --- | --- | --- | --- | --- | --- |
| L-A | `tests/tcp_fake_socket.hpp` 被注释引用但不存在，`SocketOps` 无注入入口 | **文档与实现不一致**（测试注释描述了一种不存在的机制） | 分两档：A1 不改 / A2 改 | 否 | A1 立即；A2 待裁决 | A1 ≈ 10 分钟；A2 ≈ 260 行 |
| L-B | `endpoint_alignment_declared` 未参与 XCP vs XCPplus 冲突比对 | 功能缺口，且**不需要** ABI 变更即可补 | 是（第三方 `a2l-sdk`，已获准修改） | **否**（推翻此前"必须 ABI v10"的判断） | 高 | ≈ 30 行 + 2 用例 |

**两处对先前判断的更正**（均以本次实读取证为准）：

1. 早前称"`endpoint_alignment_declared` 参与冲突比对需要 ABI v10"——**不成立**。冲突结构 `XcpPlusConflictDto` 是三个字符串（`parameter` / `xcp_value` / `xcpplus_value`），见 `thirdparty/a2l-sdk/include/liba2l/liba2l_api.hpp:396-400`；"数值相同、声明状态不同"完全可以用**新参数名**（如 `PACKET_ALIGNMENT_DECLARED`）表达，不改结构、不动 ABI。
2. 早前称"多实例只差一个 golden fixture"——**不成立**。真正断点在 SDK：`thirdparty/a2l-sdk/src/liba2l_export.cpp:1982` 与 `:2018` 只把 `GetXcpOnTcpIps().front()` 的字段填进扁平 `endpoint_*`，另加一个计数 `endpoint_instance_count`；桥接层 `thirdparty/a2l-sdk/a2lbridge/src/a2l_dto_map.cpp:453-521` 因此对每种传输只 `push_back` **一个** `TransportEndpoint`。于是 `tools/xcp_master/main.cpp:3573` 的 `++a2l_facts.instance_count` 与 `:3577` 的 `instances.push_back(...)` 在生产中**最多各触发一次**，多实例 fail-closed 分支（`tools/xcp_master/transport_selection.hpp` 规则块）只有手搓 facts 的单测能走到。

## 1 L-A：假 Socket 注入与误导注释

### 1.1 现状取证

- `tests/tcp_transport_test.cpp:10-14` 的文件头写着：

  > `2. **错误分支测试**用 tests/tcp_fake_socket.hpp 注入的假 SocketOps：partial write、EINTR、EAGAIN+可写超时、连接重置这些条件在真实 Socket 上无法确定性复现……只能用脚本化的假实现精确驱动。`

- 该文件**不存在**（`grep -rn tcp_fake_socket` 全仓只有这条注释 + 一份记录文档提到它不存在）。
- `SocketOps` 本身是完整准备的：`src/socket_util.hpp:74-160`，纯虚接口，含 `send` / `recv` / `wait_writable` / `is_would_block` / `is_interrupted` 等 20 余个方法，注释在 `:8-19` 明确说明"因此所有 Socket 调用都经过 `SocketOps`…… 测试路径注入一个按脚本行事的假实现"。
- 但**注入通道不存在**：`src/socket_util.cpp:352-354` 只有 `SocketOps& RealSocketOps() { static RealSocketOpsImpl instance; return instance; }`；`src/tcp_transport.cpp` 在 `:134`、`:284`、`:376`、`:455`、`:518`、`:615`、`:700` 共 7 处直接 `detail::RealSocketOps()`。
- `src/udp_transport.cpp` 完全不经过 `SocketOps`（直接用 `::socket` / `::ioctl` / `::closesocket`，见 `:210`、`:243`、`:263`、`:407`），所以即使补上注入，也只覆盖 TCP。
- 现有错误分支覆盖实际靠两样东西：真实回环（`tests/tcp_transport_test.cpp` 的端到端用例）+ 协议级故障注入（`tests/tcp_test_slave.hpp:69-94` 的 `TcpFaultInjection`，含 `drop_response_n` / `delay_response_n` / `corrupt_len_n` / `jump_ctr_n` / `duplicate_ctr_n` / `ctr_offset_n` / `close_after_response_n`）。

### 1.2 方案 A1（推荐先做，零风险）：把注释改成如实描述

| 动作 | 位置 | 内容 |
| --- | --- | --- |
| 改注释 | `tests/tcp_transport_test.cpp:8-14` | 第 2 条改为："错误分支目前由两类手段覆盖：① 协议级故障注入（`tests/tcp_test_slave.hpp` 的 `TcpFaultInjection`）；② 真实回环下的 EOF / 关闭打断。`SocketOps` 已按计划预留为可注入函数表，但**当前没有测试注入入口**，partial write / EINTR / EAGAIN 仍无确定性覆盖。" |
| 改注释 | `src/socket_util.hpp:8-19` | 把"测试路径注入一个按脚本行事的假实现"改为"设计上预留了注入点；当前生产路径恒为 `RealSocketOps()`，注入入口待 L-A2 决定是否补" |

**验收**：`ctest -R tcp_transport` 全绿（只改注释，必然绿）；`grep -rn tcp_fake_socket` 不再出现在源文件里。

### 1.3 方案 A2（可选，需明确批准）：真正补上注入通道

> 触发本方案的条件：你希望 partial write / EINTR / EAGAIN 有**确定性**回归，而不是靠真实 Socket 撞运气。

**设计**

1. `src/socket_util.hpp` 新增两个内部 API（带中文 doxygen）：

   ```cpp
   /// @brief 仅供测试：替换进程内 Socket 操作表（传 nullptr 恢复真实实现）
   /// @note 非线程安全地"切换"，但切换后的读取是原子的：调用方必须在
   ///       没有其它线程使用 TCP 传输时安装/卸载（测试用 RAII 守卫保证）。
   void SetSocketOpsForTesting(SocketOps* ops) noexcept;

   /// @brief 取当前生效的操作表（测试注入值，或真实实现）
   [[nodiscard]] SocketOps& CurrentSocketOps() noexcept;
   ```

2. `src/socket_util.cpp`：`std::atomic<SocketOps*> g_test_override{nullptr};`，`CurrentSocketOps()` 返回 `override ? *override : RealSocketOps()`。
3. `src/tcp_transport.cpp`：7 处 `detail::RealSocketOps()` → `detail::CurrentSocketOps()`（纯机械替换）。
4. 新增 `tests/tcp_fake_socket.hpp`：`class FakeSocketOps final : public SocketOps`
   - 每个方法一个 `std::deque<返回值>` 脚本队列 + 调用计数/参数记录；
   - 队列空时回落到"合理默认"（`wait_writable`→1、`send`→全量发送）；
   - `class ScopedFakeSocketOps`：构造时 `SetSocketOpsForTesting(&fake)`，析构时 `SetSocketOpsForTesting(nullptr)`。
5. 用例（`tests/tcp_transport_test.cpp` 新增 4 个）：
   - `SendRetriesAfterPartialWrite`：脚本 `send` 返回 `size/2` 再返回剩余 → 断言 `Send` 最终全量发出（验证补全循环）。
   - `SendRetriesAfterInterrupt`：脚本 `send` 先返回 `-1` 且 `is_interrupted()==true` → 断言重试成功。
   - `SendFailsAfterWouldBlockTimeout`：`wait_writable` 恒返回 0 → 断言抛超时错误且分类正确。
   - `RecvReportsConnectionLostOnReset`：`recv` 返回 `-1` + `is_connection_lost()==true` → 断言上报"连接已断"且不重连。
6. CMake：该测试目标加 `RUN_SERIAL TRUE`（全局覆盖状态，不能与其它测试并行）。

**风险与缓解**

| 风险 | 缓解 |
| --- | --- |
| 全局可变状态被并行测试串扰 | `ScopedFakeSocketOps` + `RUN_SERIAL`；用例内不跨线程安装/卸载 |
| 注入通道被生产代码误用 | 命名 `*ForTesting` + doxygen 明确"仅测试"；`RealSocketOps()` 语义不变 |
| 假实现与真实行为漂移，测试通过但线上仍错 | 假实现只覆盖**错误分支**，正常路径仍由真实回环用例覆盖；错误分类函数（如 `IsConnectionLostCode`）已有独立单测 |

**回滚**：`git checkout -- src/socket_util.hpp src/socket_util.cpp src/tcp_transport.cpp && rm tests/tcp_fake_socket.hpp`，并把新增 4 用例与 CMake 行回退。

## 2 L-B：`endpoint_alignment_declared` 参与冲突比对（无需 ABI v10）

### 2.1 现状取证

- 冲突结构：`thirdparty/a2l-sdk/include/liba2l/liba2l_api.hpp:396-400` —— `{parameter, xcp_value, xcpplus_value}` 三个字符串。
- 追加函数：`thirdparty/a2l-sdk/src/liba2l_export.cpp:1229-1236` 的 `AppendConflict`，**值相同则不记**。
- 对齐比对：同文件 `:1296` `AppendConflict("PACKET_ALIGNMENT", align_name(plain.endpoint_packet_alignment), align_name(plus.endpoint_packet_alignment), out)`，`align_name` 把 0/1/2 映射为 `8u << raw` —— **只比数值**。
- `endpoint_alignment_declared` 字段存在（`liba2l_api.hpp` `IfDataXcpDto`，注释见 v9 变更块），但 `DiffIfData` 从未读取它。
- 既有契约测试：`tests/a2l_golden_test.cpp:1199-1214` 的 `XcpPlusPriorityAndConflictReport` 断言 `plus_conflicts.size() == 3`（MAX_CTO / PACKET_ALIGNMENT / SUB_CMDS），其 fixture `golden_xcpplus.a2l` 的对齐是 **16 vs 32（数值不同）** → 按 §2.3 的"仅同值才追加声明行"规则，该用例数字不变。

### 2.2 语义：为什么"数值相同、声明不同"值得报

| plain 声明 | plus 声明 | 数值 | 语义差异 |
| --- | --- | --- | --- |
| 16 bit | 16 bit | 相同 | 无差异（现状不报，正确） |
| 未声明 | 未声明 | 都是默认 8 bit | 无差异（现状不报，正确） |
| **16 bit** | **未声明** | plus 取默认 8 bit | **有差异**：一个约束 16 bit，一个不约束；现状 `align_name` 会报 16 vs 8，**这条其实能报** |
| **未声明** | **8 bit（显式）** | 都是 8 bit | **有差异**：XCPplus 明确要求 8 bit，XCP 只是缺省；现状**静默通过** ← 真正的漏报 |

即：漏报只在"数值恰好相同（通常是 8 bit 默认 vs 8 bit 显式）"时发生。这类差异对 Profile 选择有实际影响——`transport_selection.hpp` 里"未声明"绝不当作"已声明 8 bit"，两者在 CLI 上是不同证据等级。

### 2.3 方案 B2（推荐）

在 `liba2l_export.cpp` 的 `PACKET_ALIGNMENT` 之后追加：

```cpp
// 声明状态差异：仅在数值相同时单独成行，避免与数值行重复。
// 规范上没有"未声明"这个值，故用可读文本表达，而不是伪造成某个位宽。
if (plain.endpoint_packet_alignment == plus.endpoint_packet_alignment &&
    plain.endpoint_alignment_declared != plus.endpoint_alignment_declared) {
    AppendConflict("PACKET_ALIGNMENT_DECLARED",
                   plain.endpoint_alignment_declared ? "已声明" : "未声明",
                   plus.endpoint_alignment_declared ? "已声明" : "未声明", out);
}
```

- **不改结构、不改 ABI 版本**。
- 既有 `size() == 3` 用例不受影响（该 fixture 两侧都声明）。
- 新增 2 个用例（内联极小 A2L，放 `tests/a2l_calibration_access_test.cpp` 同目录的新文件或既有 `tests/a2l_golden_test.cpp`）：
  - `ReportsDeclaredStateMismatchWhenValuesMatch`：plain 未声明、plus 显式 `PACKET_ALIGNMENT_8_BIT` → 1 条 `PACKET_ALIGNMENT_DECLARED`（未声明 / 已声明）。
  - `DoesNotReportDeclaredStateWhenBothAgree`：两侧都显式 8 bit → 无该行（并连带断言总数与原契约一致）。
- 文档：在 `code-plan/B-T5补漏_多实例fail-closed与SDK死字段清理.md` 的 L1 条目把"仅比数值"更新为"数值 + 声明状态（后者仅在同值时成行）"。

**备选方案（不推荐）**：B1 维持现状只改注释（省 30 行，但保留漏报）；B3 无条件比对声明状态（会产生两行，噪声大）。

**回滚**：删除该 `if` 块与 2 个用例。

## 3 L-C：多实例端点从 SDK 到 CLI 的链路断点 + golden 缺失

### 3.1 现状取证（本项的真正断点）

1. 上游能表达多个端点：`thirdparty/a2llib/include/a2l/xcp/xcpdatablock.h:46` `GetXcpOnTcpIps()` 返回 `std::vector<XcpOnTcpIp>&`（`:76` 成员 `xcp_on_tcp_list_`）；解析器每个 `XCP_ON_TCP_IP` 块都 `SaveXcpOnTcpIp()`（`thirdparty/a2llib/src/xcp/xcpdataparser.y:1163`）。
2. SDK 只导出**第一个**：`thirdparty/a2l-sdk/src/liba2l_export.cpp:1982` 与 `:2018` 填 `dto->endpoint_instance_count`，端点字段一律取 `.front()`。
3. 桥接层因此每种传输只产出一个 `TransportEndpoint`（`thirdparty/a2l-sdk/a2lbridge/src/a2l_dto_map.cpp:453-521`，整块只有一次 `transports->push_back`）。
4. CLI 侧逻辑本身已写好：`tools/xcp_master/main.cpp:3565-3600` 遍历 `xcp_info->transports` 压 `a2l_facts.instances`；`tools/xcp_master/transport_selection.hpp` 的规则块对 `instances.size() > 1` 做去重后 fail-closed。**但输入端永远只有 0 或 1 个元素**，所以该规则在生产中不可达。
5. 测试现状：`TransportSelection.*` 的多实例 3 个用例手工构造 `A2lTransportFacts::instances`，能验证纯函数，但**没有一条路径证明"真实 A2L 的两个端点会被解析出来"**。
6. golden 生成器也不支持：`tests/a2l_gen/gen_a2l.py:355-378` 只发射 `XCP_ON_UDP_IP`，**没有 `XCP_ON_TCP_IP`**，且每个 IF_DATA 块只允许一个端点。

### 3.2 方案（三步，ABI v10 在此落地）

#### 第 1 步：SDK 暴露全部端点（ABI 9 → 10）

`thirdparty/a2l-sdk/include/liba2l/liba2l_api.hpp`：

```cpp
/// @brief 单个传输层端点事实（ASAM AE MCD-1 §1.4.3 XCPonTCP/IP、XCPonUDP/IP）
struct IfDataXcpEndpointDto {
    std::string kind;                          ///< "TCP" / "UDP" / "CAN" / "FLX" / "USB" / "SXI"
    std::uint16_t port = 0;                    ///< 端口
    std::string host_name;                     ///< HOST_NAME
    std::string ipv4_address;                  ///< ADDRESS（IPv4 文本）
    std::string ipv6_address;                  ///< IPV6
    std::uint8_t packet_alignment = 0;         ///< 原码 0/1/2 = 8/16/32 bit
    bool alignment_declared = false;           ///< 是否显式写了 PACKET_ALIGNMENT
    std::vector<std::uint8_t> sub_commands;    ///< OPTIONAL_TL_SUBCMD
    std::uint16_t transport_version = 0;       ///< 该端点声明的 TL 版本
};

// IfDataXcpDto 内新增：
std::vector<IfDataXcpEndpointDto> endpoints;   ///< 全部端点（按 A2L 出现顺序）
```

`kLibA2lAbiVersion` 8 → 9 的注释块后追加 v10 段：说明"新增 `endpoints` 向量；原 `endpoint_*` 扁平字段**保留并继续填第一个端点**，语义为'首选端点'，不删除以免一次性破坏所有消费者"。

#### 第 2 步：SDK 导出与桥接层遍历

- `liba2l_export.cpp`：新增 `FillEndpointList(blk, dto)`，遍历 `GetXcpOnTcpIps()` 与 `GetXcpOnUdpIps()` 全部元素填 `endpoints`；现有扁平赋值改为读 `endpoints.front()`（或按 kind 取该类第一个，与现状等价），保证旧断言逐位不变。
- `a2l_dto_map.cpp`：`ConvertIfDataXcp` 改为遍历 `dto.endpoints` 逐个 `push_back`（`kind` 字符串 → `TransportEndpoint::Kind` 映射；未知 kind 跳过并保持不臆造）；`instance_count` 语义细化为"该类传输的实例数"，并行保留。
- **兼容性**：`TransportEndpoint::instance_count` 已存在（`a2lbridge/include/libxcp/a2l/if_data_xcp.hpp`），CLI 无需改代码；但 `a2l_facts.instances` 会真正收到多个元素 → 多实例 fail-closed 从"不可达"变为"可达"。

#### 第 3 步：generator + golden fixture

- `tests/a2l_gen/gen_a2l.py`：`emit_if_data` 增加 `XCP_ON_TCP_IP` 发射（字段集与 UDP 对齐：`PACKET_ALIGNMENT` / `OPTIONAL_TL_SUBCMD` / `HOST_NAME` / `ADDRESS` / `IPV6`），并把端点从"单数 key"改为"列表 key"，支持一个块内多项（保持旧 spec 兼容：单数形式视为长度 1 的列表）。
- 新增变体 `golden_multi_endpoint.a2l`：同一 `IF_DATA XCP` 下两个 `XCP_ON_TCP_IP`，端口/主机/对齐各不相同（例如 `6000 @192.168.0.20 PACKET_ALIGNMENT_8_BIT` 与 `6001 @192.168.0.21 PACKET_ALIGNMENT_16_BIT`）。
- 用例：
  1. `A2lGolden.TcpEndpointsAreAllExported`：`endpoint_instance_count == 2`、`endpoints.size() == 2`、字段逐项核对。
  2. `A2lGolden.BridgeKeepsBothTcpEndpoints`：桥接层 `transports` 里两个 `TcpIp`，`instance_count == 2`。
  3. `TransportSelection.RejectsAmbiguousTcpEndpointsFromGolden`：用 golden 解析结果构造 facts，断言 fail-closed 且错误文本含两个端点摘要（现有文案已含）。

### 3.3 风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| ABI 10 破坏下游 | 只新增字段，旧字段保留并语义不变 | 同一仓库内 `a2lbridge` 与 CLI 一起改；golden 期望值逐项复核 |
| 多实例规则从"不可达"变"可达"，可能让以前能跑的 A2L 现在报错 | 正是计划 §7.3 的意图（宁可 fail-closed 也不猜） | 错误文本给出两个端点明细 + 提示 `--host/--port` |
| 生成器改动影响既有 golden | 旧 spec 单数形式映射为长度 1 列表 | `gen_a2l.py` 保持向后兼容；跑全量 golden 比对 |
| 上游某些 A2L 的 `XCP_ON_TCP_IP` 顺序不稳定 | 顺序影响 `front()` 语义 | `endpoints` 按出现顺序稳定输出；扁平字段=出现顺序第一个（与今天 `front()` 一致） |

**回滚**：`git checkout -- thirdparty/a2l-sdk tests/a2l_gen/gen_a2l.py tests/a2l_golden_test.cpp`，删除新变体与 3 个用例。

- 早前对 `tools/xcp_master/main.cpp` 的实测是 **3684 处** replacement —— 说明这不是个别文件手抖，而是全仓风格与当前 clang-format 版本存在系统性差异（很可能是用更老版本写的）。

### 4.2 三个选项

| 选项 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| D1（推荐） | 不加全仓门禁；**新增文件**必须 0 漂移，CI 只检查 `git diff --diff-filter=A` 得到的新文件 | 零历史 diff；债不扩大 | 存量债仍在 |
| D2 | 一次性全仓 `clang-format -i` | 一步到位 | 巨大 diff（main.cpp 3684 处）；`git blame` 大面积失效；审查成本极高 |
| D3 | 每次改动顺手格式化整文件 | 渐进收敛 | 与 AGENTS.md "不要重构已完成代码"冲突；审查里混入大量无关 diff |

### 4.3 D1 的落地细节

- `.github/workflows/` 新增（或并入既有 workflow）一个 job：
  ```bash
  pip install clang-format==22.1.0
  git diff --name-only --diff-filter=A origin/${{ github.base_ref }}...HEAD -- '*.cpp' '*.hpp' > new_files.txt
  xargs -a new_files.txt -r clang-format --dry-run --Werror
  ```
  版本必须**钉死**，否则不同 clang-format 版本会互相打架。
- 立即做的小事：把本批次新增的 `src/tcp_framing_negotiation.cpp`（10 处）与 `include/libxcp/tcp_framing_negotiation.hpp` 格式化干净；`transport_selection.hpp` 只人工对齐**新增段落**，不做整文件格式化（避免 109 处无关 diff）。
