## 0. 结论速览

卡顿与网络、从站、glog 写盘无关，是 **UI 线程上两处 O(候选数) 热路径被高频触发**：

| 阶段 | 区间 | 时长 | 帧数 | 帧率 | 整表重建 | UI 线程占用 |
|---|---|---|---|---|---|---|
| A 仅渲染 | 10:49:24 → 10:51:46 | 142.5 s | 465 | **3.26 fps** | 4 次 | ~58.8% |
| B 渲染+重建 | 10:51:46 → 10:53:16 | 90.1 s | 82 | **0.91 fps** | **174 次** | **~81.9%** |

| 指标 | 实测 |
|---|---|
| 候选行数 | **198,556**（全库符号一次性进列表） |
| `UI 整表重建耗时` | 178 次，中位 **337.7 ms**，均值 340.7 ms，峰值 575.6 ms，累计 60.6 s |
| `UI 单帧构建耗时` | 547 次，中位 **177.0 ms**，p90 184.1 ms，峰值 393.3 ms，累计 98.3 s（547/547 全部 >50 ms） |
| 每秒汇总 | 193 窗口，平均 **2.85 帧/秒** |
| 启动期 | A2L 加载 4,835.5 ms；候选检索 94.7 ms；应用搜索结果 444.2 ms |
| 采样 | `0xF4` 轮询 1,500 次、8 次/s，全程 0 超时（网络与从站正常） |

## 1. 根因：四级放大

1. **全库无上限进列表** —— `FindPreviewCandidates()` 用 `database_.Search(query, Count())`，`*` 直接拿 198,556 条。
2. **每帧渲染 O(行数)** —— FTXUI `MenuBase::OnRender()`（`cmake-build-release/_deps/ftxui-src/src/ftxui/component/menu.cpp:102`）逐条构造 Element；`frame`/`vscroll_indicator` 只裁剪绘制。198k 行 ≈ 177 ms/帧，而可视区只有约 20 行 → **99.99% 的构造是无效功**。
3. **一次值刷新被放大成整表重建** —— [main.cpp:1292](../tools/xcp_master/main.cpp) `UpdatePreviewLabel()` 中，仅"非展开且非仅采样"才走"只改一行"的分支；一旦命中 `expanded_preview_names_.contains(name)` 就 `RebuildPreviewLabels()`（[main.cpp:1105](../tools/xcp_master/main.cpp)），清空并重建 198k 个标签 + 3 张哈希表，335 ms。
4. **触发频率远超消费能力** —— 阶段 B 轮询 8 次/s，合并器（[main.cpp:1474](../tools/xcp_master/main.cpp) `RequestPreviewRefresh()` + single-flight 的 `SchedulePreviewRefresh()`）只能压到 **1.93 次/s**，因为单次重建就 335 ms。

日志佐证阶段切换：`展开后 198556 行` 在 **10:51:49.186 变为 198557 行**（新增 1 行展开），此后 90 秒内 174 次重建；**展开一个正在刷新的变量 = 打开"每 0.5 s 卡一次"的开关**。

结论：**候选基数 198k 决定单次代价，展开+采样决定触发频率**，两者相乘就是观感上的"卡死"。

## 4. P1 设计：增量刷新（D2）

### 4.1 现状缺陷

`RebuildPreviewLabels()` 把"生成行布局"（`BuildPreviewRows`，结构变化才需要）与"格式化每行文本"（值变化就要刷新）耦合在同一个函数里。于是**任何一行文本变化都触发整个 198k 行重建**。

### 4.2 设计

**第一步：把逐行格式化下沉为独立函数**（本次重构的唯一核心）。

```cpp
/**
 * @brief 按当前观测状态格式化一行预览文本。
 * @param row 行布局描述（父行/子行/占位行/读取动作行）。
 * @return 该行显示文本；符号已失效时返回失效提示。
 * @note 调用方必须持有 output_mutex_ 与 watched_mutex_。
 */
std::string FormatPreviewRowLabel(const PreviewRow& row) const;
```

它内部完成当前 `for (const auto& row : preview_rows_)` 循环体里的取值与分支：符号查找、样本查找、watched 判定、读取不可用原因、父行 `FormatPreviewLabel` / 子行 `FormatExpandedArrayValue` / `FormatExpandedScalarValue` / 占位行状态文案。**分支逻辑逐字复制，不重写语义**。

`RebuildPreviewLabels()` 循环体变为：

```cpp
preview_rows_ = BuildPreviewRows(row_sources);
for (std::size_t index = 0; index < preview_rows_.size(); ++index) {
    const auto& row = preview_rows_[index];
    preview_visible_names_.push_back(row.symbol_name);
    preview_row_indices_[row.symbol_name].push_back(index);   // 新增索引
    if (!row.is_child)
        preview_visible_index_.try_emplace(row.symbol_name, preview_labels_.size());
    preview_labels_.push_back(FormatPreviewRowLabel(row));
}
```

**第二步：新增 `name → 行索引集合` 映射**（`std::unordered_map<std::string, std::vector<std::size_t>> preview_row_indices_;`），一个符号展开后有 1 个父行 + N 个子行，全部登记。

**第三步：`UpdatePreviewLabel()` 去掉 rebuild 分支**：

```cpp
void UpdatePreviewLabel(const std::string& name) {
    const auto rows = preview_row_indices_.find(name);
    if (rows == preview_row_indices_.end()) return;   // 不在可见行集合
    std::lock_guard lock(output_mutex_);
    std::lock_guard watched_lock(watched_mutex_);
    for (const auto index : rows->second)
        preview_labels_[index] = FormatPreviewRowLabel(preview_rows_[index]);
}
```

### 4.3 复杂度

| 场景 | 现状 | 改造后 |
|---|---|---|
| 非展开行刷新 | O(1)（已是增量） | O(1) |
| **展开行刷新** | **O(n)=335 ms** | **O(k)，k=该符号行数（≤10）→ µs 级** |
| 结构变化（展开/折叠、范围切换、搜索结果） | O(n) | O(n)（保持不变，用户单次操作） |

### 4.4 边界与并发

- `preview_row_indices_` 与 `preview_rows_`/`preview_labels_` 同生命周期，逐次重建时 `clear()`。
- 原 `preview_visible_index_` 保留（`UpdatePreviewLabel` 之外的调用方仍在用）。
- 锁序与现状一致：先 `output_mutex_` 后 `watched_mutex_`，与 `RebuildPreviewLabels()` 相同，不引入新锁。
- 占位行（`preview_labels_` 比 `preview_rows_` 多 1 行）不登记索引，重建时的选择保持逻辑不动。

### 4.5 P1 测试

| 用例 | 断言 |
|---|---|
| `FormatsEveryRowKindConsistently` | 同一 rows 分别走"重建"与"逐行格式化"，文本逐行相等（父行/子行/占位行/读取动作行/失效符号 5 类） |
| `ExpandedRowRefreshTouchesOnlyItsRows` | 展开 A（3 子行）后刷新 A：`preview_labels_` 中 A 的 4 行变化、其余行**逐字节不变**（哨兵法：把其他行填成固定串再刷新） |
| `CollapsedRowRefreshKeepsRowCount` | 折叠态刷新不改变行数与选中项 |
| `ExpandedRefreshCostIndependentOfCandidateCount` | 用 200k 假行灌入后刷新 1 次，耗时 < 5 ms（防回归的粗粒度门禁） |

## 5. P2 设计：列表虚拟化（D1）

### 5.1 现状

`Menu(&preview_labels_, &preview_selected_, preview_options)`（[main.cpp:488](../tools/xcp_master/main.cpp)）把整个 `preview_labels_` 交给 FTXUI，渲染时逐条构造。FTXUI 没有虚拟化开关。

### 5.2 纯函数：窗口计算（可单测、不含 FTXUI）

新增 `tools/xcp_master/preview_window.hpp`：

```cpp
/** @brief 虚拟列表的可视窗口：起始行与行数。 */
struct PreviewWindowBounds {
    std::size_t first{0U};  /**< 窗口首行（0 基）。 */
    std::size_t count{0U};  /**< 窗口行数。 */
};

/**
 * @brief 计算虚拟列表应渲染的窗口，必要时滚动以保持选中行可见。
 * @param total 总行数。
 * @param selected 当前选中行（0 基，超界自动钳位）。
 * @param visible_rows 可视行数（≥1）。
 * @param current_first 上一次窗口首行，用于避免抖动。
 * @return 新的窗口边界。
 */
inline PreviewWindowBounds ComputePreviewWindow(std::size_t total,
                                               std::size_t selected,
                                               std::size_t visible_rows,
                                               std::size_t current_first);
```

规则（逐条与测试对应）：

| 情形 | 结果 |
|---|---|
| `total == 0` | `{0, 0}` |
| `total <= visible_rows` | `{0, total}`（不滚动） |
| 选中在窗口内 | 保持 `current_first`（**不抖动**） |
| 选中 < 窗口首行 | `first = selected` |
| 选中 ≥ 首行+行数 | `first = selected + 1 - count` |
| `current_first` 超界 | 钳位到 `total - count` |

### 5.3 组件：`WindowedMenu`

新增 `tools/xcp_master/windowed_menu.hpp`（header-only，仅 `xcp_master` 目标使用）：

```cpp
/**
 * @brief 只构造可视行的虚拟菜单，替代 FTXUI Menu 以保证 198k 行下仍可交互。
 * @note 渲染复杂度 O(可视行数)，与候选总数无关。
 */
class WindowedMenu final : public ftxui::ComponentBase {
public:
    WindowedMenu(const std::vector<std::string>* entries, int* selected,
                 WindowedMenuOptions options);
    void SetVisibleRows(std::size_t rows);           ///< 每帧由布局刷新
    std::size_t LastRenderedRows() const;            ///< 测试用：上一帧实际构造行数
    bool Focusable() const override { return true; }
    ftxui::Element OnRender() override;
    bool OnEvent(ftxui::Event event) override;
};
```

渲染：`vbox` 内按 `ComputePreviewWindow` 只构造 `count` 行；选中行 `inverted`，聚焦行加 `focus`；行文本直接用 `preview_labels_[i]`（与原 Menu 的 `DefaultOptionTransform` 一致）。

### 5.4 交互等价性矩阵（实现必须逐项对齐）

| 事件 | FTXUI Menu 现状 | WindowedMenu 目标 |
|---|---|---|
| `ArrowUp` / `k` | 选中上移一格（到顶部为止） | 相同 |
| `ArrowDown` / `j` | 选中下移一格 | 相同 |
| `PageUp` / `PageDown` | 按可视页移动 | 相同（步长 = `visible_rows`） |
| `Home` / `End` | 首/末行 | 相同 |
| `Tab` / `TabReverse` | 选中下/上一格（Menu 自行吞掉） | 相同（保持"不切换焦点"） |
| `Return` | 触发 `preview_options.on_enter` | 相同（`ActivatePreviewRow()`） |
| 鼠标滚轮 | 上/下滚 3 行 | 相同 |
| 鼠标左键点击 | 选中并聚焦所点行 | 相同（由窗口边界换算全局行） |
| `Left` / `Right` / `h` / `l` | 纵向菜单下无动作 | 相同（不消费，交上层） |
