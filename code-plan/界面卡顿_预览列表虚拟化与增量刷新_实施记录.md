## 0. 结论速览

| 指标 | 改造前（现场日志实测） | 改造后（headless 基准实测） | 结论 |
|---|---|---|---|
| 单帧渲染（198,556 行） | 中位 **177.0 ms**（547 帧，累计 98.3 s） | **0.02 ms**（只构造 20 可视行） | 与候选总数解耦 |
| 单次采样触发的列表重建 | 中位 **337.7 ms**（178 次，累计 60.6 s） | **0.001 ms**（只刷新该符号的行） | 与候选总数解耦 |
| 真实界面帧率 | 阶段 A 3.26 fps / 阶段 B 0.91 fps | 未实机复测（见 §4） | 待现场复测 |
| UI 线程占用 | 阶段 A 58.8% / 阶段 B 81.9% | 未实机复测（见 §4） | 待现场复测 |

改造前的数字取自现场日志
`cmake-build-release/tools/xcp_master/logs/tools/xcp_master/xcp_master.INFO.20261024-104922.4319.glog`
（16,064 行，10:49:22–10:53:16，候选 198,556 行；阶段 B 从 10:51:49 展开一个符号后开始）。

**核心结论**：卡顿来自「候选行数 × 每帧/每次采样都做 O(n) 工作」，与 A2L 文件字节数无关；
两个 O(n) 点（渲染、重建）都已改为与可视/受影响行数成正比。

## 2. 行为等价性

### 2.1 菜单交互（逐项对照 `cmake-build-release/_deps/ftxui-src/src/ftxui/component/menu.cpp`）

| 事件 | 原 FTXUI Menu | 现在 WindowedMenu |
|---|---|---|
| `ArrowUp` / `k` | 选中 −1（钳位） | 相同 |
| `ArrowDown` / `j` | 选中 +1（钳位） | 相同 |
| `PageUp` / `PageDown` | 按可视高度移动 | 相同（步长 = 可视行数） |
| `Home` / `End` | 首行 / 末行 | 相同 |
| `Tab` / `TabReverse` | 选中循环移动，不切换焦点 | 相同（Q1 决策：保持现状） |
| `Return` | 触发 `on_enter` | 相同（`ActivatePreviewRow()`） |
| 滚轮上/下 | 3 行 | 相同（Q2 决策：保留鼠标） |
| 左键点击 | 选中并聚焦所点行 | 相同（窗口内命中 → 换算全局行号） |
| `ArrowLeft` / `ArrowRight` / `h` / `l` | 纵向菜单无动作、不消费 | 相同（显式返回 false 交上层） |

另外保留了两处隐式契约：

- 选中行越界时写回钳位后的值（对应 `MenuBase::Clamp()`），避免过滤后 `ActivatePreviewRow()` 索引到不存在的行；
- 选中行高亮用 `inverted`、聚焦时叠加 `focus`，与 `DefaultOptionTransform` 的观感一致。

### 2.2 行文本

整表重建与增量刷新共用 `FormatPreviewRowLabel()`，分支顺序与文案逐字沿用改造前实现
（候选失效 / 父行 / 单次读取动作行 / 占位行五档状态 / 数组元素行 / 标量子行 / 无样本），
因此两条路径不会产生不同文本。

### 2.3 滚动条

按 Q3 决策移除 `vscroll_indicator`（虚拟化后它只会恒等于"满格"，反而误导），
改在面板内新增一行「第 a–b / N 行」；窗口首行取自 `ComputePreviewWindow()`，与渲染同源。

## 4. 未验证项与已知偏离

1. **真实 TUI 未实机复测**：`xcp_master` 要求真实 TTY，本环境 `pty.openpty()` 报
   `out of pty devices`，`/bin/ps` 亦被沙箱拒绝。因此 §0 表中「帧率/UI 线程占用」两行
   仍为改造前数据，需在带终端机器上复测（复测方法见计划 §6）。
2. **键盘/鼠标交互未经人工核对**：§2.1 的对齐依据是 `menu.cpp` 源码逐分支比对 + headless
   渲染用例，未做真机按键验证。建议现场核对 Tab、滚轮、点击三处手感。
3. **整表重建仍为 O(n)**：搜索、范围切换、展开/折叠、模态关闭后应用结果等结构性变化
   依旧重建一次（原来每次采样重建一次，现在只在结构变化时重建）。若后续仍需消除，
   属于计划 §9 明确排除的范围（需要行布局增量算法）。
4. **候选上限未引入**：计划 D3（候选数上限）未在本次范围内，候选仍可能达到 198k。
