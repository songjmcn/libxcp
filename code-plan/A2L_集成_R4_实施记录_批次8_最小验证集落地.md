### 1.3 关键实现决策（均有源码证据支撑）

1. **多行 `/begin IF_DATA XCP … /end IF_DATA` 合法**：主干 `a2lflexer.l` 的
   `"/begin"{ws}"IF_DATA"` → `A2lScanner::ReadIfData()` 整段吞入直到 `/endIF_DATA`
   （跳空白匹配、保留换行），XCP 子词法器对换行不敏感。生成器因此采用多行版式。
2. **`ADDRESS_GRANULARITY_BYTE` 在 PROTOCOL_LAYER 中仅占位**：`xcpdataparser.y` 的
   protocol_layer 动作只调用 `SetByteOrder($13)`，从不调用 `SetAddressGranularity`
   （表在 `protocollayer.cpp` 却无消费点），故 `GetAddressGranularity()` 恒为默认
   BYTE=1 —— 冒烟按此事实断言（`== Byte`），并在注释中标注为上游已知行为。
3. **XCP 子词法器对 `0x…` 返回 UINT token**（`xcpdataflexer.l` hexnumber 规则），
   DAQ/ODT_ENTRY 的十六进制合法。
4. **DAQ_LIST 必须嵌套于 DAQ 块内**（daq_optional → daq_list），生成器按此排版；
   DAQ 块 token 顺序 = type max_daq max_event min_daq optimisation addr_ext id_field
   granularity max_odt_entry_size overload（含 GRANULARITY 的 11-token 变体）。
5. **Odt/OdtEntry 布局冻结直传**（`daqlist.h` 的 POD struct），SDK 侧不做解释；
   符号归属反查放 bridge 的 `ResolveDaqListSymbols`（歧义地址留空，禁止猜测）。
6. **MODULE 级 IF_DATA 优先于 PROJECT 级**：`ExtractIfDataXcp` 在首个含有效块的
   module 上取值并 break；生成样本将 IF_DATA 放在 MODULE 内。
7. **DTO 帧的 envelope**：`DtoFrameLayout` 默认 1 字节 PID + Absolute 标识无附加头，
   `Decode` 用 `pid==list.number` 匹配 EPK；净荷长度必须恰好等于冻结布局总字节数。

### 2.4 已知限制（首里程碑范围）
- 上游 PROTOCOL_LAYER 不消费 `ADDRESS_GRANULARITY` ident（见 §1.3-2），bridge
  按上游事实取值；如需 WORD/DWORD 粒度需上游补丁或 SDK 层独立导出（未修改上游）。
- t1..t7 / OPTIONAL_CMD 明细 / SEED_AND_KEY 外部函数尚未透传到领域快照
  （§6.3 已知缺口，`IfDataXcpDto` 已预留字段）。
- CHARACTERISTIC 的 RECORD_LAYOUT 元素类型推导未实现（SDK 统一 `kUnknown`，
  bridge 依 B-3 显式拒绝数值读写 —— 冒烟以负例锁定该行为）。
- `DaqInfo.max_daq` 取列表数下界（保守值）；OVERLOAD/TIMESTAMP 位保持默认。
- Debug 构建的 CRT 匹配、Linux/macOS、安装规则、CI 矩阵、时序 SLA 均不在
  最小开发验证集范围（§2 明确排除）。
