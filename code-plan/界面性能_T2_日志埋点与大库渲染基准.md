# 界面性能 T2：日志埋点 + 大库渲染基准（实施记录）

> 任务来源：用户报障「A2L 文件太大后，交互响应慢」，要求先看日志分析、不改代码；
> 分析完成后经用户裁决（m04388）实施 **T2 = 加性能日志 + headless 渲染基准**，
> 样本取 **合成 40 MB（约 198k 符号）+ 可选真实文件覆盖**。

## 0. 结论速览

| 结论 | 证据 |
| --- | --- |
| 慢的根因是**候选行数**，不是 A2L 文件字节数 | 198 556 条候选单帧渲染 169.7–227.5 ms（≈6 fps）；41.5 MB→1.6 s 只是启动一次性成本 |
| 渲染成本**线性**于候选数，无虚拟化 | 49 639 行 48.3 ms → 198 556 行 193.1 ms，比值 **4.00**（候选数比 4.00） |
| 日志里那 323 次「响应长度错误」是与 A2L 无关的**独立缺陷** | 全部发生在 20:09:26 首次 1 s 超时之后（INFO 第 2638 行起） |
| UI 侧此前**零日志**，无法自证瓶颈 | `grep -n "a2l\|A2L"` 在 INFO 日志中无命中；帧耗时只能靠探针外推 |

## 1. 定位过程的实测数字（供后续对照）

### 1.1 现场 A2L（`~/Downloads/apa_complex.a2l`）

- 规模：87 MB / 246 783 行；`/begin MEASUREMENT` 195 998、`/begin CHARACTERISTIC` 2 558；`Count()` = 198 556。
- 探针实测（`.tmp/probe/perf_probe.cpp`）：`Load` 3 384–3 389 ms；`Search("*", max=Count)` 89.4 ms；`Search("*apa_control_status*")` 60.9 ms；`Find(限定名)` ×1000 = 0.1 ms（哈希路径）。
- 峰值 RSS：1.09 GB（仅加载）/ 1.25 GB（再持有一份全量符号副本）。

### 1.2 渲染成本（FTXUI `Menu`，headless）

`.tmp/probe/menu_render_probe.cpp`（80×24，5 帧平均）：2 739 条 → 2.0 ms；50 000 条 → 42.0 ms；198 556 条 → **169.7 ms**。

源码定位：`cmake-build-release/_deps/ftxui-src/src/ftxui/component/menu.cpp:102` 的 `MenuBase::OnRender()`
`for (int i = 0; i < size(); ++i)` 逐条构造 Element，**没有任何虚拟化**；`frame` / `vscroll_indicator` 只影响绘制裁剪。
`tools/xcp_master/main.cpp:774`（改造前行号）把整个 `preview_labels_` 交给该 Menu。

### 1.3 日志分析（与 A2L 大小无关的独立缺陷）

- INFO 日志 `xcp_master.INFO.20261023-200800.20149.glog` 共 6 230 行，20:08:00 → 20:10:49；580 次 `0xF4`（SHORT_UPLOAD）轮询，8 字节与 1 字节符号交替；RTT 中位 **7.9 ms**。
- 3 次 1 000 ms 超时（20:09:26 / 20:10:27 / 20:10:46），每次走 `Recovering → ERR_CMD_SYNCH → Connected`。
- 首次超时后出现 **323 次** `XCP 响应长度错误 cmd=0xF4 actual_bytes=1 expected_bytes=8`，从 INFO 第 2638 行持续到第 6228 行。
- 机制：1 字节请求（ctr=258）于 25.278 发出、26.562 才回（1.28 s）→ 超时恢复期间该迟到响应占住响应槽 → 新请求发出即被「响应槽已消费」（第 2626 行）拿走旧数据 → 此后每个响应都匹配到下一个等待者，**永久错位一拍**。
- 后果：`src/command_executor.cpp:619` 的 `CheckResLength` 抛 `MalformedPacket`，读取报失败；相邻两次请求长度相同时会**静默串值**（潜在数据错位）。
- 轮询周期窗口统计（8 字节请求起点中位）：504.9 / 465.6 / 513.4 / 474.9 / 403.6 / 508.7 / 566.3 / 380.8 ms —— 围绕配置的 500 ms 抖动，**无随时间劣化**，故日志不能证明 UI 拖慢采集。

## 2. 日志埋点（`tools/xcp_master/main.cpp`）

统一用文件级 `PerfStopwatch`（`steady_clock`，提供 `ElapsedMs()` / `ElapsedSeconds()`），日志走 `LIBXCP_LOG_INFO`（`std::format` 语法）。

| # | 位置 | 记录内容 | 级别/频率 |
| --- | --- | --- | --- |
| 1 | `main()` 的 `A2lBridge::Load` 前后 | `A2L 加载耗时 X ms（N 个符号 / 路径）` | INFO，每次启动 1 条 |
| 2 | `main()` 的启动全库检索（DAQ 事件绑定） | `A2L 启动全库检索耗时 X ms（命中 N 个）` | INFO，每次启动 1 条 |
| 3 | `FindPreviewCandidates()` | `UI 候选检索耗时 X ms（模式 / 命中 / 库内共）` | INFO，每次搜索 1 条 |
| 4 | `ApplyPreviewSearchResult()` | `UI 应用搜索结果耗时 X ms（N 个候选，筛选 …）` | INFO，每次搜索 1 条 |
| 5 | `RebuildPreviewLabels()` | `UI 整表重建耗时 X ms（候选 N / 展开后 M 行 / 范围 …）` | INFO，每次重建 1 条 |
| 6 | 根渲染器 lambda → `NoteFrameRendered()` | 单帧 ≥ 50 ms 时 `UI 单帧构建耗时 …`（WARNING）；每 1 s 汇总一次均值/峰值（INFO） | 阈值 + 每秒汇总 |

设计要点（避免"观测扰动被测对象"）：

- 逐帧日志会自己成为瓶颈（glog 同步写盘），因此**低于 50 ms 的帧只累加计数**，不写盘；`kFramePerfWarnMs = 50.0`、`kFramePerfWindowSeconds = 1.0`。
- 聚合状态（`frame_perf_frames_` / `frame_perf_total_ms_` / `frame_perf_max_ms_` / `frame_perf_window_start_`）只在界面线程访问，故不加锁。
- 单帧统计的是「元素树构建 + 菜单条目生成」耗时。`ComponentBase::Render()`（`_deps/ftxui-src/src/ftxui/component/component.cpp:125`）是**急切**调用 `OnRender()`，因此 Menu 的 O(n) 条目构建包含在内；像素级绘制阶段不计入，其量级由基准测试覆盖。

## 3. 基准测试（`tests/xcp_master_render_bench_test.cpp`）

headless 渲染，不需要 TTY（`Screen::Create` + `Render`），接线与主程序一致：`Menu` 外套
`vscroll_indicator | frame | size(HEIGHT, LESS_THAN, 20) | flex`。

| 用例 | 输入 | 断言 | 本机实测 |
| --- | --- | --- | --- |
| `RendersFrameWithFieldSizeCandidateList` | 198 556 条候选标签 | < 参考×3（510 ms）且 < 硬上限 1 500 ms | **227.5 / 232.9 ms**（两次运行） |
| `RenderCostGrowsLinearlyWithCandidateCount` | 49 639 vs 198 556 | 耗时比 < 8（候选数比 4） | 47.7 → 199.2 ms，比值 **4.17**（另一次 4.00） |
| `SearchesAndFiltersLargeA2lWithinBudget` | 40 MB 合成样本（198 422 符号）| 检索 < 参考×3（270 ms）且 < 1 500 ms；过滤 < 180 ms 且 < 1 200 ms | 加载 1 634–1 644 ms；检索 **34.8–39.8 ms**；过滤 **1.8–7.4 ms** |

预算常量（沿用 `A2lGolden` 的「实测值 ×3 放宽 + 绝对上限」范式，非 SLA）：

| 常量 | 值 | 来源 |
| --- | --- | --- |
| `kFrameRenderReferenceMs` | 170.0 | 探针在真实 87 MB 上的单帧实测 169.7 ms |
| `kFrameRenderHardLimitMs` | 1500.0 | 量级门 |
| `kSearchReferenceMs` | 90.0 | 真实 87 MB 上 89.4 ms（合成样本只有 39.8 ms，故有余量） |
| `kSearchHardLimitMs` | 1500.0 | 量级门 |
| `kFilterReferenceMs` | 60.0 | 真实文件长符号名下的候选拷贝成本 |
| `kFilterHardLimitMs` | 1200.0 | 量级门 |

样本获取（两路，优先级从高到低）：

1. 环境变量 `LIBXCP_UI_PERF_A2L=<真实 A2L 路径>`（真实文件不入库）；
2. 构建期注入 `XCP_UI_PERF_A2L="<build>/tests/a2l_gen/golden_perf_40mb.a2l"`，由 ctest 夹具 `a2l_ui_perf_gen` 生成；
3. 都不存在 → `GTEST_SKIP`，避免在缺样本机器上误报。

## 4. CMake 接线（`tests/CMakeLists.txt`）

- 新增夹具生成：`add_test(NAME a2l_ui_perf_gen … gen_a2l.py --out … --perf 40)` + `FIXTURES_SETUP A2lUiPerf`。
- 新目标 `XcpMasterRenderBenchTest` 放在既有 `if(LIBXCP_BUILD_TOOLS)` 块内，并再套一层 `if(TARGET ftxui::ftxui)`：
  FTXUI 由 `tools/xcp_master/CMakeLists.txt` 用 FetchContent 引入，而 `add_subdirectory(tools)` 先于 `add_subdirectory(tests)`，
  因此 tests 作用域里只能判断目标是否存在，**不能重复 FetchContent**。
- 链接 `libxcp::a2lbridge` + `ftxui::ftxui` + `GTest::gtest` + `libxcp_test_main`；POST_BUILD 复制 `liba2l`（运行时加载）。
- 夹具属性用 `gtest_discover_tests(… PROPERTIES FIXTURES_REQUIRED A2lUiPerf)` 设置（构建期才发现用例名，无法按用例名 `set_tests_properties`）。

## 5. 附带修复：`tests/a2l_gen/gen_a2l.py` 的 Python 版本依赖

原代码用 `Path.write_text(..., newline="")`（**需要 Python 3.10+**），而构建机 `Python3_EXECUTABLE` 是 miniconda 3.9
→ `a2l_perf_gen` 一直失败（`TypeError: write_text() got an unexpected keyword argument 'newline'`），
并连带 `ParseLargeFileUnderBudget` 因缺样本 Not Run。已改为 `open(..., newline="")`，两个 `--perf` 分支都改。

## 6. 测试结果

- 构建：`cmake -B cmake-build-release -S . -DCMAKE_BUILD_TYPE=Release -DLIBXCP_BUILD_TESTS=ON -DLIBXCP_BUILD_TOOLS=ON` + 全量构建通过。
- `cmake-build-release/tests/XcpMasterRenderBenchTest` → **3 passed**（3.5 s）。
- 全量 `ctest -j 4` → **972 项，1 failed**（55.61 s）。唯一失败是既有的 `ExampleXcpIntegrationDemoCppDemo`。
- 由本次修复转绿的既有失败：`a2l_perf_gen`、`ParseLargeFileUnderBudget`（此前 3 项失败中的 2 项）。

## 7. 未验证项（如实记录）

- **TUI 运行时日志未实测**：`xcp_master` 要求真实 TTY（`main.cpp` 的 `IsInteractiveTerminal()` 检查在加载之前），
  本环境 `pty.openpty()` 报 `out of pty devices`、`/bin/ps` 被沙箱拒绝，无法构造伪终端。
  埋点正确性由编译与代码审阅保证；运行时数值需在有终端的机器上用真实 A2L 复跑：
  ```
  LIBXCP_UI_PERF_A2L=~/Downloads/apa_complex.a2l ./cmake-build-release/tests/XcpMasterRenderBenchTest
  ./cmake-build-release/tools/xcp_master/xcp_master --a2l ~/Downloads/apa_complex.a2l --host … --port …
  # 然后在 logs/tools/xcp_master/*.INFO.*.glog 里过滤 "UI " / "A2L 加载耗时"
  ```
- 渲染用例的预算是**量级门**，不是 SLA；不同机器（尤其 CI）需按实测重新校准参考值。
