## 2. 改法

### 2.1 C-01：NULL DACL 必须判为不可信

把 ACL 判定的公共逻辑抽成 `CheckAclByHandle()`，`GetSecurityInfo` 返回 `dacl == nullptr`
时**直接判不安全**并给出明确理由：

```cpp
    bool safe = true;
    if (dacl == nullptr) {
        *violation = "没有 DACL（Null DACL 等价于所有人完全控制）";
        safe = false;
    } else { … }
```

旧实现是 `if (dacl != nullptr) { …循环… }`，NULL DACL 直接跳过检查，等于给"所有人完全
控制"的目录发通行证。

### 2.2 C-02：继承 ACE 计入判定，且文件自身也要查

两处改动：

1. `CheckAclByHandle(..., bool include_inherit_only, ...)` 增加继承项开关；只有
   `include_inherit_only == false` 才跳过 `INHERIT_ONLY_ACE`。
2. `CheckRootChain()` 逐级向上时，**快照目录本身**传 `true`（它的子文件会继承它的 ACE），
   祖先目录传 `false`（祖先只需阻止他人删除/替换本路径，继承项不影响该判定）。
3. `StageFileImpl()` 在快照文件以只读句柄打开后、读回校验前，**再对文件本身做一次 ACL
   判定**，失败则删除该文件并失败关闭。这样即使目录 ACL 有遗漏，也不会把"文件继承到
   `Everyone:(F)`"的快照交给 SDK。

### 2.3 M-01：用例必须锚定"拒绝点就是自己构造的目录"

原用例只断言 `result.trusted == false` 与"理由里含某类关键词"。问题在于：只要**祖先目录**
不合格，被测函数同样会拒绝，用例照样通过——安全判定本身被关掉时测不出来。

改造：

- 负向用例自己构造被污染的目录（Windows 用 `SetNullDacl()` / `SetDaclFromSddl()`，
  POSIX 用 `fs::permissions(..., all, replace)`），构造失败一律 `ASSERT_TRUE` 而不是 SKIP。
- 新增断言：`EXPECT_NE(result.reason.find(root.string()), std::string::npos)`，把"拒绝点"
  钉在用例自己构造的目录上。
- 新增 Windows-only 用例 `RejectsRootWithInheritOnlyEveryoneWrite`，SDDL 为
  `D:(A;OICIIO;FA;;;WD)(A;;FA;;;OW)(A;;FA;;;SY)(A;;FA;;;BA)`：Everyone 完全控制但仅继承，
  目录自身"看不见"这份权限，里面的文件却会继承。

### 2.4 M-02：`RecoveryFailed` 改为未决，而不是拒绝

`ClassifyFramingFailure()` 增加独立分支：

```cpp
        case ErrorCategory::RecoveryFailed:
            // 命令超时后用 SYNCH 恢复也没拿到确认：对端既没有按本候选的帧
            // 格式给出应答，也没有返回任何可判读的协议层拒绝证据。
            return FramingVerdict::Inconclusive;
```

`tools/xcp_master/main.cpp` 的未决提示同步改为先查"地址/端口/对端是否在运行/是否启用
XCP"，再提帧布局，避免把用户直接引向 `PACKET_ALIGNMENT`。

### 2.5 M-05：README 去掉已删除的选项

四处措辞改为"按从站上报的能力自动选择"，并明确"`--daq-profile` 不存在"。当前 README 中
`--daq-profile` 只出现在"没有这个选项"的说明句里。

## 5. 已知局限

- 3 条"快照成功路径"用例在本机与 WSL 上都被 SKIP：`FindPrivateBase()` 的候选（可执行文件
  目录、`%LOCALAPPDATA%`、系统临时目录）都不是"仅本人可写"的目录（本机项目树带沙箱注入的
  非可信写 ACE，WSL 的 `/tmp` 同理），被测函数正确地拒绝了它们。这是环境事实，不是缺陷。
- `RejectsRootWithInheritOnlyEveryoneWrite` 只能在 Windows 上编译（依赖 SDDL），POSIX 侧
  由 `RejectsWorldWritableRootOnPosix` 覆盖同类语义。
- 变异脚本放在 `.tmp/`（未跟踪），不属于交付物；复现方式见脚本头部注释。

## 8. 追加修复（CI 上两个负向用例红）

### 8.1 现象

批次 4 推送后在 MSBuild workflow 上测试失败，注解只给出用例名（`Annotate failures` 只读
`LastTestsFailed.log`，不含断言文本；job 日志匿名下载 403）：

```
1021:SnapshotTest.RejectsRootWritableByOthers
1022:SnapshotTest.RejectsRootWithInheritOnlyEveryoneWrite
```

### 8.2 根因

`.trusted` 在 CI 上同样是 `false`（C-01/C-02 的安全判定没有失效）。红的是批次 4 新加的
**拒绝点锚定断言**：`StageTrustedA2lSnapshot` 上报的拒绝点是**快照根之上的目录**（用例基
目录 `dir_` 或其祖先，理由是"写权限授予了非可信主体 …"），该路径里不含 `root` 子串，
`reason.find(root.string())` 得 `npos`。

之所以会落在祖先：`SnapshotTest::SetUp` 把用例基目录建在 `fs::temp_directory_path()` 下，
而 CI runner 的系统临时目录本身带"非可信主体可写"的 ACE（旁证：同一 run 里 3 条快照成功
路径用例全部 SKIP，说明 `FindPrivateBase()` 一个"仅本人可写"目录都没找到）。本机之所以
绿，是因为本机该随机后缀子目录的父链恰好干净，拒绝恰好落在 `root` 上。

即：**安全判定正确，是测试用例对"拒绝点必须精确落在自己污染的目录"这一假设在 CI 的
TMP 权限环境下不成立**。

### 8.3 改法（`tests/a2l_trusted_snapshot_test.cpp`）

1. 用例基目录不再用系统临时目录：`SnapshotTest::SetUp` 改为
   `fs_platform::ExecutableDirectory() / "libxcp_snapshot_<seed>_<n>"`（`fs_platform` =
   `calmcar::xcp::detail::fs`，头文件 `src/detail/fs/trusted_snapshot_platform.hpp`）。
   构建产物目录由构建过程创建，祖先链可控且仅本人可写；取不到可执行文件目录直接
   `ASSERT` 失败，**不再回退到 TMP**，避免悄悄退回原缺陷。
2. `FindPrivateBase()` 候选顺序改为"可执行文件目录 → `%LOCALAPPDATA%` → 系统临时目录"，
   让成功路径用例优先在可控目录上探测。
3. 锚定断言改用新辅助函数 `ReasonMentionsPath(reason, target)`：同时接受原始形、绝对形与
   `weakly_canonical` 规范形。被测函数内部会规范路径，在符号链接、8.3 短文件名或 `\?\`
   前缀目录下，规范形与用例传入的原始字符串可能不同——只比较原始串会让"拒绝点正确"的
   用例在个别机器上误报失败。
