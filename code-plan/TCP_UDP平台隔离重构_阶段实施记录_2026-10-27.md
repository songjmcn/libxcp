## 本次完整构建与测试（Windows / MSVC 14.44 / Ninja / Release）

### 构建流程

1. `cmake --build cmake-build-release --target clean` → 成功（`Cleaning... 276 files.`，exit 0）。
2. `cmake -B cmake-build-release -S . -DCMAKE_BUILD_TYPE=Release -DLIBXCP_BUILD_TESTS=ON` → 成功，缓存确认 `LIBXCP_BUILD_TESTS:BOOL=ON`。
3. `cmake --build cmake-build-release -j 4` → 需在 MSVC 开发者环境中执行，见下文“环境注意事项”。
4. `ctest --output-on-failure -j 4` → 最终 1055/1055 通过。

### 环境注意事项（复现必需）

- **长时间无输出会被误判为挂起**：直接把构建/测试输出接管道时，`clean`/`build` 曾在 10 分钟内无任何输出、进程 CPU 停在 0.03s。改为 `</dev/null >log 2>&1` 重定向到文件后，`clean` 立即完成。后续命令一律先重定向到日志再读日志，不要把长时间构建输出接管道。
- **必须在 MSVC 开发者环境构建**：直接在普通 shell 里跑 `cmake --build` 会让 `cl.exe` 找不到标准库头，报 `fatal error C1083: 无法打开包括文件: “cstdint”/“cstddef”/“optional”`。这是因为 Ninja + MSVC 依赖 `vcvars64.bat` 设置的 `INCLUDE`/`LIB`。本次通过 `vswhere` 定位 VS 2022 Community 后 `call vcvars64.bat` 再构建。辅助脚本落在构建目录（不入库）：`cmake-build-release/build-msvc.bat`。
- **本机沙箱阻止新建可执行文件写用户 Temp**：所有“向 `%TEMP%` 建目录”的用例（24 个）报 `create_directories: Access is denied.`。用一个最小 MSVC 程序实测：写 `%TEMP%`、写 `C:\Users\<user>\` 均失败，写工作区内目录成功；而 pwsh/.NET/Python 在 `%TEMP%` 建目录正常。结论是环境限制，不是代码缺陷。为避免掩盖问题，没有改测试，而是把测试进程的 `TMP`/`TEMP` 重定向到 `cmake-build-release/ctest-tmp`（工作区内）后再跑 CTest，脚本为 `cmake-build-release/run-ctest.bat`；重定向后这 24 个用例全部通过。

### 构建中修复的问题

- `tests/tcp_fake_socket_test.cpp` 编译失败：`error C2039: "inet_pton": 不是 global namespace 的成员`、`error C2065: “socklen_t”: 未声明的标识符`。原因是平台分离后 `socket_util.hpp` 不再传递平台头，该测试失去了对 `ws2tcpip.h` 的间接包含。已在 `_WIN32` 分支显式加入 `#include <ws2tcpip.h>` 并注明原因。
- 全量 `clang-format` 检查发现新文件不合规（`socket_ops_win.cpp` 62 处、`socket_ops_posix.cpp` 67 处，另 `socket_util.cpp`、`tcp_transport.cpp`、`udp_transport.cpp`、`socket_ops_pod_test.cpp`、`tcp_fake_socket.hpp` 各有少量），已按 `.clang-format` 就地格式化，复查全部为 0 处；格式化后重新构建并整轮测试仍全绿。
