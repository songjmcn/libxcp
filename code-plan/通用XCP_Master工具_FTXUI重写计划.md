# 通用 XCP Master 工具 FTXUI 重写计划

## 0. 状态、目标与批准边界

- 状态：用户已于 m00119 批准本文方案并授权实施；用户随后授权恢复现有 `thirdparty/a2llib` 子模块、在项目自有 `thirdparty/a2l-sdk` 集成层修改平台构建逻辑（不改 a2llib 子模块源码或 Boost）。该层现以 Boost.Locale 替代上游 logger 的 chrono tzdb 源文件，并显式链接 Boost.Locale。Boost 1.86.0 和 FTXUI 7.0.3 已成功配置；用户批准后修复 `tests/xcp_daq_test.cpp:114` 的 narrowing 转换。AppleClang Release 全目标构建成功，Python 3.12 下全量 CTest 共 514 项、0 失败、1 项按用例预期显式跳过。GCC 15 仍需 ABI 匹配的 Boost.Locale；Windows/Linux 尚未验证。详情见《通用XCP_Master工具_FTXUI重写实施记录.md》。
- 目标：用 FTXUI 重写 `tools/xcp_master/` 的交互层，将命令操作区和显示区分离，解决后台 poll/DAQ 输出干扰正在输入的命令的问题。
- 已确认新增 A 档标量标定界面：提供独立“变量标定”视图，支持 `CHARACTERISTIC/VALUE` 的搜索、读取、目标值编辑、确认写入及回读。仅复用现有标量 Calibration 能力，不宣称完整支持全部 XCP Calibration 功能；不包含标定页管理、数组、曲线或 MAP。该实施范围已包含于 m00119 批准。
- FTXUI 不加入 submodule、不复制到 `thirdparty/`；仅在 CMake 启用 `LIBXCP_BUILD_TOOLS` 时自动获取。
- 保留工具现有 UDP、A2L、poll/DAQ、读写及安全约束；不修改协议核心公共接口，不扩展支持的传输、符号类型或 Slave 能力。
- 实施按获批范围修改工具内部源码、CMake、测试与文档；另按用户授权修改项目自有 `thirdparty/a2l-sdk` 集成层。不得修改 `thirdparty/a2llib` 子模块源码、Boost 或协议核心公共接口；不在本阶段执行设备标定写入。

## 2. 范围与兼容性

### 2.1 保留

- 可执行文件名 `xcp_master`。
- 参数 `--a2l`、`--host`、`--port`、`--module`、`--mode poll|daq`、`--interval-ms`、`--daq-profile generic|xcplite` 及 `--help`。
- 命令 `list [pattern]`、`list all`、`more`、`info`、`add`、`remove`、`read`、`watch`、`stop`、`write`、`help`、`quit`。
- list 默认每页 40 项；list 只查询 A2L，不读取实时值。
- poll 默认周期目标 500 ms，立即开始首轮读取，不保证硬实时。
- DAQ 事件驱动；generic 与显式 XCPlite profile 分离，DAQ 运行时拒绝 read/write/add/remove。
- 写入资格、字节序/地址粒度校验、人工确认和写后回读；每次 DAQ 清表重新确认。

### 2.2 不做

- 不重构 `src/`、`include/` 已完成的库实现；不修改 third-party 子模块 `thirdparty/a2llib` 或 Boost。仅在用户明确授权时修改项目自有的 `thirdparty/a2l-sdk` 集成层。
- 不复用 examples 源码，不启动或管理 cpp_demo。
- 不增加 TCP/CAN、自动 Seed&Key、自动重连、自动恢复标定值或旧 DAQ 配置。
- 不增加数组、曲线、结构体读写、绘图、文件导出、批量无确认写入。
- 第一版不增加符号自动补全或复杂按钮菜单；变量标定视图仅提供搜索、选择、读取和写入所需的最小控件。
- 不增加标定页查询/切换、工作页/参考页管理、页复制或 Flash 持久化；本次 Calibration 限定为既有标量内存读写，不保证断电保存。

### 2.3 建议的终端兼容策略

- 帮助与参数错误在初始化 FTXUI 前输出，保留现有退出码语义：帮助 0、参数错误 2、运行失败 1。
- 正常交互启动要求交互终端；重定向或不支持全屏交互时明确报错，不静默进入不可用界面。
- 第一版不同时维护旧文本 REPL。该行为变化已随 m00119 获批；正常交互启动要求 stdin/stdout 为终端，帮助与参数错误仍可重定向输出。

## 3. UI 详细设计

### 3.1 固定框架

```text
┌─ XCP Master ─────────────────────────────────────────────────────────┐
│ UDP 192.168.1.10:5555 │ 已连接 │ POLL │ 运行中 │ 周期目标 500 ms       │
│ A2L: demo.a2l        │ MODULE: ECU    │ 已选变量 3                    │
├─ 显示区 ─────────────────────────────────────────────────────────────┤
│ [观测值]  变量标定  命令结果  日志                                   │
│                                                                      │
│ 变量                      最新值    单位    更新时间       状态       │
│ ECU::EngineSpeed          1530      rpm     14:32:01.200    正常       │
│ ECU::CoolantTemperature   86.5      °C      14:32:01.205    正常       │
│ ECU::VehicleSpeed         —         km/h    14:32:00.700    超时       │
│                                                                      │
│ POLL：按目标周期依次读取，不保证硬实时                                 │
├─ 命令操作区 ─────────────────────────────────────────────────────────┤
│ xcp> read ECU::EngineSpeed▏                                           │
│ Enter 执行 │ ↑↓ 历史 │ Tab 焦点 │ F2 视图 │ F5 停止采集              │
└──────────────────────────────────────────────────────────────────────┘
```

示意数据不是默认 ECU 配置。状态栏固定两行，底部命令区约 3～4 行，显示区使用剩余空间。完整布局建议最小尺寸 80×24。

### 3.2 状态栏

显示端点、连接状态、poll/DAQ 模式、generic/XCPlite profile、采集状态、所选变量数量、A2L 文件和 MODULE 过滤条件。poll 显示周期目标；DAQ 不显示误导性的轮询周期。

忙碌时区分“正在读取”“等待确认”“正在配置 DAQ”“正在停止”“正在退出”。不把本机显示刷新频率标为 ECU 采集频率。

### 3.3 观测值视图

- 一行对应一个选中变量，主键为规范名 `module::name`；包含最新值、单位、本机更新时间和状态。
- add 后立即出现“待读取”行，不自动访问 ECU；remove 后移除该行。
- poll/DAQ 更新对应行，不持续追加普通样本日志。
- 读取失败或无效样本显示 `—` 和失败状态；若保留上次成功值，必须明确标注，不能冒充当前有效值。
- stop 后保留数据并标记“已停止”。DAQ ECU 时间戳作为独立字段/详情展示，与本机更新时间分开。
- 变量较多时滚动；长名称截断但选中行可查看完整名称。
- 显示更新合并/队列淘汰计数。不得把显示侧淘汰误称为网络丢包或 ECU 丢样。
- 建议显示刷新上限 10 次/秒；该数值仅用于 UI 合并，不改变 poll 周期或 DAQ 事件周期。

### 3.3.1 变量标定视图（A 档，已确认纳入范围）

作为上方显示区的第四类视图，与观测值、命令结果、日志并列；下方命令输入区仍固定保留。不要求用户手动拼写 write 命令即可完成标量标定。

```text
┌─ 显示区 ─────────────────────────────────────────────────────────────┐
│ 观测值  [变量标定]  命令结果  日志                                   │
│ 搜索：TargetSpeed________  [搜索]   MODULE：ECU                       │
│ 名称                      类型                   写入资格            │
│ > ECU::TargetSpeed        CHARACTERISTIC/VALUE    候选                │
│   ECU::ReadonlyLimit      CHARACTERISTIC/VALUE    只读                │
│                                                                      │
│ 已选：ECU::TargetSpeed      单位：rpm                                 │
│ 当前值：1200               读取时间：14:32:01.200                    │
│ 目标值：[1500____________]  [读取当前值] [申请写入…]                  │
│ 结果：尚未写入；所有写入均需单独确认                                  │
├─ 命令操作区 ─────────────────────────────────────────────────────────┤
│ xcp>                                                                │
└──────────────────────────────────────────────────────────────────────┘
```

**目录与选择**

- 搜索遵守现有 MODULE 过滤和规范名规则；显示标量 CHARACTERISTIC/VALUE，包括只读/不支持项并说明原因，MEASUREMENT 不列为可写标定项。
- 候选资格复用 SymbolWriteUnsupportedReason 等现有策略；候选不等于 ECU 已授权。数组、位域、未知宽度/地址或不可逆换算等继续保守拒绝。
- 搜索、选择变量只访问 A2L，不自动扫描 ECU。候选列表分页/滚动，不因为符号多而一次读取全部标定量。

**当前值与编辑**

- 选中后显示规范名、类型、单位、支持状态；元数据存在且契约可核验时显示 A2L 物理范围，否则显示“未提供”，不猜测字段或范围。
- “读取当前值”异步单次读取，显示完成时间和失败原因；初始显示“未读取”。历史值不得标为新读取结果。
- 目标值是独立编辑草稿，刷新当前值不能覆盖草稿或抢焦点。切换变量时清除目标草稿，避免将上一变量的目标值误用于新变量。
- 数值解析复用既有策略，保留有符号/无符号 64 位整数精度，拒绝非有限数值。提交前执行逆换算、编码宽度、字节序、地址粒度及可核验的范围检查；无法安全编码则拒绝。

**标定流程与反馈**

1. 选择变量并编辑物理目标值。
2. 点击“申请写入…”后，通过共享业务路径校验资格、编码目标，并重新读取当前值；读取失败不得进入写入确认。
3. 打开 §3.7 弹窗，展示本次新读取的当前值、目标值、单位及风险；默认取消。
4. 仅在明确确认且上下文有效后发送标量写入，再按原路径读取实际值。
5. 在标定视图内显示写入/回读结果，并同步记录命令结果和日志；不因结果到达自动离开标定视图。

回读成功只表示获得实际值；如比较目标与实际值，按编码类型及换算精度定义判据，不用字符串相等判断一致。出现差异必须显示目标值与实际值。回读失败显示“写入命令成功，实际值未知”，不保留绿色成功状态。

**命令、焦点与运行约束**

- 表单操作和 read/write 命令调用同一校验、确认和执行路径，不构造可被名称/文本注入的命令字符串，不复制一套弱化安全的写入实现。
- Tab/Shift+Tab 在当前视图的搜索框、列表、目标编辑、按钮和固定命令框之间切换；↑/↓ 在列表焦点下选择变量，不触发命令历史；Enter 在目标编辑框不得直接写入 ECU。
- DAQ 运行期间可浏览目录/编辑草稿，但读取和申请写入按钮禁用并提示“请先 stop”；即使从快捷键或命令进入，业务层也必须拒绝。
- poll 模式遵守同一串行调度和确认快照规则；普通操作忙碌或已有确认弹窗时禁止再提交另一写入请求，允许请求 stop/quit。
- 确认期间锁定目标变量和目标值；选择/会话变化使确认失效。输入事件不得穿透弹窗。

### 3.4 命令结果视图

- 每条命令回显与其结果关联，区分成功、警告、失败。
- list 保留 40 项分页及 more；list all 查询完整集合，仅渲染可见行，不因日志容量上限静默丢掉目录结果。
- info 按字段显示类型、地址、宽度、单位、事件列表和读写资格，不把“候选”写成 ECU 已授权。
- read 显示规范名、物理值、单位和错误；保留原有整数精度。
- 用户向上滚动时，新结果不强制跳到底部，显示新结果提示。
- 从命令框发起的普通命令完成可激活结果视图；标定表单发起的操作保持变量标定视图，并同步记录结果。后台采样不自动切换视图或输入焦点。确认弹窗期间不切换底层交互。

### 3.5 日志视图

记录连接、采集启停、配置失败、超时及退出事件，不逐样本重复日志。显示本机时间和 INFO/WARN/ERROR 标签；颜色仅作辅助。

重复错误可合并计数。建议普通日志和命令结果历史各保留最多 2000 条记录；单条过长内容需要可浏览的截断提示。目录查询结果独立管理，不受历史条数截断影响。

### 3.6 命令输入、历史和焦点

- 固定单行输入，长命令水平滚动；数据刷新不修改输入内容、光标或焦点。
- Enter 提交，空输入不执行。↑/↓ 浏览历史，返回编辑位置时恢复草稿。建议历史最多 200 条。
- 支持常规光标移动、删除和粘贴；多行粘贴不自动执行多条命令，提交前提示或拒绝换行内容。
- Tab/Shift+Tab 在输入和显示区间切换；F2 循环视图；显示区有焦点时 PgUp/PgDn 滚动；F5 请求 stop；Esc 取消弹窗或返回输入。
- 所有快捷键必须在三平台终端验证；命令仍是主要入口，不依赖某个快捷键才能停止或退出。
- 网络操作期间允许编辑、滚动和停止。第一版不积压普通命令队列，重复提交明确提示忙碌；stop/quit 为控制请求，不排在普通命令后等待。

### 3.7 写入确认

弹窗显示规范名、当前值、目标值、单位和 ECU 权限提示，按钮为“取消”“确认写入”。默认焦点为取消；打开弹窗的 Enter 不得穿透为确认。

确认绑定本次操作 ID、变量、编码后的目标值和会话状态；确认不可复用于另一条命令。Esc、退出或会话失效均取消。确认等待期间不持有命令互斥锁，也不阻塞 UI 线程。

确认后必须重新核验上下文；poll 模式下其他写命令不可穿插，轮询读可继续，但当前值属于确认准备时的快照，应标注读取时间。回读结果明确区分写失败、写成功且回读成功、写成功但回读失败，不自动重试或恢复旧值。

### 3.8 DAQ 清表确认

弹窗显示 profile、变量数量、本地计划摘要及警告：“FREE_DAQ 将清除 Slave 全部动态 DAQ 配置，停止后不恢复原配置。”按钮为“取消”“清表并启动”，默认取消。

顺序为：本地资格检查与运行时能力查询 → 本地规划 → 本次确认 → 配置与启动。取消不得发送 FREE_DAQ。每次启动重新确认；待确认期间冻结该次选择，上下文变化使确认失效。

### 3.9 尺寸和终端生命周期

缩小时隐藏次要列/压缩帮助，不覆盖输入区。极小窗口提示尺寸不足，仍提供停止、取消和退出。终端调整大小不影响业务状态。

退出、初始化失败和异常清理都需恢复终端模式与光标。不能把 UI 消失当作后台采集已停止；退出流程必须完成线程与会话清理。

## 4. 组件与数据流

仅在工具内部进行必要拆分，沿用现有库接口与符号策略。建议文件职责如下，最终数量以最小可测试边界为准：

| 工具内部职责 | 建议落点 |
|---|---|
| 参数、A2L/连接初始化、生命期协调 | `tools/xcp_master/main.cpp` |
| 命令解析与业务执行、确认准备/提交 | `tools/xcp_master/master_controller.hpp/.cpp` |
| UI 模型、结构化结果、观测快照、有界事件缓冲 | `tools/xcp_master/ui_model.hpp/.cpp` |
| FTXUI 布局、输入、焦点、弹窗、事件循环 | `tools/xcp_master/tui_app.hpp/.cpp` |
| 现有符号读写资格 | `tools/xcp_master/symbol_policy.hpp`，优先不改 |

### 4.1 线程所有权

- UI 主线程唯一持有和操作 FTXUI 组件及渲染模型；不调用阻塞的 XCP 请求，不使用 getline 进行确认。
- 业务执行线程串行处理用户操作及 poll 读取/DAQ 配置/停止，避免多个工具线程交错发送 Master 操作。保留库内部 DTO 线程，不重构核心。
- DAQ 回调只发布必要样本事件，不打印、不修改 FTXUI，不等待 UI 消费。采用有界缓冲或按变量合并的最新快照。
- 后台通知通过 FTXUI 支持的跨线程事件机制唤醒 UI；具体 API 在实施前查证固定版本文档和头文件。通知合并，避免每帧入队一个无限增长的 UI 事件。
- 不依赖 UI 高刷新率解决网络操作响应问题；停止优先级在业务调度中处理。

### 4.2 数据流

1. 输入提交 → 命令解析 → 本地校验 → 业务线程执行。
2. 读/写/配置结果 → 结构化事件 → UI 模型 → 命令结果/日志。
3. poll 样本或 DAQ 回调 → 有界样本缓冲/最新快照 → UI 合并刷新观测表。
4. 危险操作准备 → ConfirmationRequest → 弹窗 → 带操作 ID 的确认/取消 → 业务线程核验后执行或释放。
5. stop/quit → 控制标志唤醒 → 在途请求返回或超时 → 停止会话、结束线程 → 断开连接 → 退出 UI。

建议沿用 256 的样本缓冲上限起步，增加可见淘汰计数；控制结果和确认事件不得被采样洪峰淘汰。普通命令不积压，结束事件必须可靠投递。字符串格式化尽量移出 DTO 回调。

### 4.3 生命周期与停止

UI、控制器、数据库、MeasurementSession 和 Master 的生命周期由入口统一管理。先取消待确认操作、请求停止，停止回调发布并回收业务线程，再销毁 UI 接收对象和依赖资源。

停止不能强行中断既有同步 XCP 请求。UI 显示“等待在途请求结束/超时”，不承诺即时停止。异常路径与正常退出共用清理策略，避免回调访问已销毁对象、死锁或 join 卡在终端输入。

## 5. CMake 与 FTXUI 获取

- 继续使用 `LIBXCP_BUILD_TOOLS` 默认 OFF；只有进入 tools 构建分支才声明并获取 FTXUI。
- 使用 CMake FetchContent；固定发布版本及不可变源码校验信息，不追踪 main/master，不使用浮动标签作为唯一保证。
- 实施前已核验上游：FTXUI v7.0.3，Git 提交 `f921fad208912747c17d129a8ef75ec7624b6eec`，官方 Git 仓库 `https://github.com/ArthurSonzogni/FTXUI`，许可证为 MIT；根 CMake 定义 `ftxui::ftxui`，关闭 docs/examples/tests/install 的选项名为 `FTXUI_BUILD_DOCS`、`FTXUI_BUILD_EXAMPLES`、`FTXUI_BUILD_TESTS`、`FTXUI_ENABLE_INSTALL`；`App::Post`、`PostEvent`、`Exit` 可用于跨线程唤醒，Windows/Linux/macOS 支持按上游 README 声明。AppleClang 21.0.0.21000334 下已完成 Release 配置、全目标构建与 CTest；Windows/Linux 尚待实际平台验证。
- 仅工具内部目标以 PRIVATE 方式链接所需 FTXUI 组件，不污染核心/A2L SDK 的公共依赖。
- 关闭 FTXUI 自身示例、测试、文档与安装功能，使用固定版本实际支持的配置变量；不覆盖用户的全局编译配置。
- 默认下载/构建目录位于构建树，源码仓库不增加 submodule 或 thirdparty 副本。
- 支持 CMake 标准 FetchContent 本地源码覆盖机制，用于离线源码；离线输入应匹配固定版本并记录来源。已有完整缓存可复用，缺失缓存时明确报错，不声称无条件离线可构建。
- 下载失败使 tools=ON 配置失败并提供版本、来源和离线覆盖指引，不静默退回旧 UI。
- 保留 A2L 动态库部署逻辑。tools=ON 不自动开启 EXAMPLES/XCPlite；tools=OFF 即便 tests/examples 开启也不得获取 FTXUI。

## 6. 错误和安全边界

- 参数错误、A2L 加载失败、连接失败在 UI 前处理；启动后命令错误、超时和采集失败进入结果/日志及相关变量状态。
- 使用既有结构化错误与类型，不根据显示字符串猜业务错误码。
- 写入权限不由 A2L 可写标记保证；保持地址范围、宽度、标量布局、字节序、粒度和换算检查。
- DAQ 保持唯一 FIXED_EVENT_LIST、profile 能力与资源限制；不因新 UI 放宽协议支持。
- 拒绝/取消确认、断线与重复提交不得发送危险命令；确认令牌单次有效。
- 样本合并、显示队列淘汰和网络问题分别计数/描述。刷新失败不伪造有效值。

## 7. 测试与验收建议

m00119 批准自动化测试为必需、真实 Slave 联测可选。所有新增测试放入 `tests/`，不依赖 examples 或真实 ECU。

### 7.1 自动化

- 保留 CLI help、缺参、poll/DAQ 参数互斥和 SymbolPolicy 测试。
- 增加命令解析/历史、观测行更新、失败值展示、状态切换、滚动跟随策略和缓存上限测试。
- 标定视图测试：MODULE/名称过滤、只读项拒绝、搜索不访问 ECU、读取结果与草稿隔离、切换变量清空草稿、整数精度、非有限值/不可编码目标拒绝、写前重新读取失败不确认、成功写入与回读差异/失败分别展示。
- 校验表单与命令共享安全路径；DAQ 期间按钮禁用及业务层拒绝，重复点击只产生一次请求，表单 Enter 不直接写入，取消/过期确认零写命令。
- 确认测试：默认取消、Esc、重复 Enter、重复确认、过期操作 ID、退出取消；取消写入零写命令、取消 DAQ 零 FREE_DAQ。
- 业务并发测试：网络操作不在 UI 线程执行，Master 操作串行；stop 优先处理但等待在途超时；DAQ 回调洪峰不阻塞接收，不无限增长缓存。
- 生命周期测试：配置失败、启动失败、读取超时、停止异常、退出时仍有回调；不得产生销毁后访问或遗漏线程。
- 渲染/事件测试：用可控尺寸和模拟事件验证固定输入区、焦点保持、弹窗和小窗口布局。FTXUI 测试设施须先核验；不把只测模型当作完整终端验证。
- 新业务测试使用模拟 Transport/可控 UDP 对端及现有 A2L fixture，不需要自动开启 XCPlite。

本次实现状态：已新增标量布局/写入策略、有界面板行缓冲、命令历史/草稿恢复及确认状态模型 GTest 用例，但因项目配置缺少 Boost CONFIG 尚未在正式测试目标中执行。上述视图状态/渲染、确认线程时序、业务并发、生命周期场景仍未覆盖；当前状态集中在第 9 节与《通用XCP_Master工具_FTXUI重写实施记录.md》，不得视为已通过。

### 7.2 构建门验证

| 配置 | 验收 |
|---|---|
| tools OFF、tests ON | 不获取/构建 FTXUI，既有测试不增加 UI 依赖。 |
| tools OFF、examples ON | 不获取 FTXUI，examples/XCPlite 既有行为不变。 |
| tools ON、tests OFF、examples OFF | 首次配置自动获取固定 FTXUI，可独立构建 xcp_master。 |

| tools ON、有效本地 FTXUI 源码覆盖 | 不访问 FTXUI 下载来源，可构建工具；其他项目依赖另按既有规则准备。 |
| tools ON、来源不可达且无本地源 | 配置明确失败，无静默降级。 |

使用 Release。完整构建前按仓库要求先清理；按实际生成器设置 `--config Release`、并行参数。不运行 install/Debug/bin 的所有测试，不执行 install。三平台结果分别记录，单平台通过不写成三平台通过。

### 7.3 手工终端验收

Windows/Linux/macOS 上检查：中文/单位对齐、长命令编辑、粘贴、历史、快捷键、窗口缩放、滚动、确认弹窗、退出恢复终端。持续采集时输入内容/光标/焦点不变，超时期间仍可操作界面。

可选真实授权 Slave：浏览、poll/DAQ 更新、stop、非关键标定量确认与回读。真实设备缺失时标记未执行，不能用模拟结果替代。终端自动化涉及伪终端时按平台分别实现/验证，不能假设三平台接口相同。
