# 传输层（Transport）

> 归属：`include/libxcp/ixcp_transport.hpp`、`udp_*.hpp`、`src/udp_*.cpp`
> 本文档描述 libxcp 的传输层抽象与 XCP on UDP/IP 实现。

## 1. 模块定位

协议核心通过 `IXcpTransport` 抽象接口收发 XCP Packet，不感知具体传输介质。
v1.0 提供标准 XCP on UDP/IP 实现；CAN/CAN FD 传输为后续版本，预留实现位
（见 `code-plan/libxcp_measurement_architecture.md` §25/§26）。

## 2. 组成文件

| 文件 | 职责 |
|---|---|
| `ixcp_transport.hpp` | 传输层抽象接口 `IXcpTransport` 与包监听器 `IPacketListener` |
| `udp_transport.hpp` / `udp_transport.cpp` | 标准 XCP 1.1 Part 3 UDP/IP 实现（跨平台 IPv4 Socket） |
| `udp_header_codec.hpp` / `udp_header_codec.cpp` | 4 字节 Transport Header（LEN/CTR）纯函数编解码 |
| `udp_transport_config.hpp` | 端点与行为配置（本地/远端地址端口、MAX_FRAME_PACKET_SIZE、来源过滤策略等） |

## 3. 关键接口

### `IPacketListener`

Transport 内部线程收到完整 Packet 后回调；**在 Transport 工作线程执行**，
实现者需保证线程安全、不得在回调内做阻塞式长操作：

- `OnPacketReceived(BytesView packet)` — 完整 XCP Packet（不含 Transport
  Header）；`packet` 仅在本次回调期间有效，异步保存必须自行复制字节
- `OnTransportClosed(std::string_view reason)` — 通道关闭（正常/错误），返回后
  不再有 `OnPacketReceived`
- `OnTransportWarning(std::string_view message)` — 可恢复错误（如畸形
  Datagram 丢弃），Transport 不因此关闭

### `IXcpTransport`

- `Open(IPacketListener&)` — 打开通道，内部接收线程启动；失败抛
  `XcpException(TransportError)`
- `Close()` — 关闭通道，幂等
- 发送完整 CTO Packet（不含 Transport Header）

## 4. UDP 接收 CTR 策略（项目策略，见 `udp_transport.hpp` §8.1）

1. 一个 UDP Datagram 按 LEN 顺序解出多个完整 Frame；每个 Frame 独立执行 CTR 检查
2. 首个合法 Frame 建立 `m_last_recv_ctr_` 基线，接收并推进
3. `CTR == 期望值`（`last + 1 mod 65536`）→ 接收，推进
4. 前向跳号（模 65536 差值 1..32767）→ 接收当前 Frame，报告缺口，推进
5. 重复或后向乱序 → 丢弃该 Frame，报告诊断
6. 恰好相差 0x8000 → 歧义，丢弃该 Frame，报告诊断
7. Datagram 内任一 Frame 的 Header/LEN 越界或有尾部残留 → 整体丢弃该 Datagram
8. `Open()` 时发送 CTR 置 0、清空接收基线；XCP Session 重连不单独重置
9. 不在 Transport 层重排或重传 Frame；命令超时与恢复由 `CommandExecutor` 负责

## 5. 依赖

- 平台 Socket：Windows 需显式链接 `ws2_32`（根 `CMakeLists.txt` 已处理）
- 协议核心只依赖本接口，不依赖任何 Socket API（`tests/mock_transport.hpp`
  可替换为 mock 供 L2 测试）
