# 第三方依赖（thirdparty）

> 归属：`thirdparty/`（未经明确指示不得修改任何文件）
> 本文档描述 libxcp 依赖的第三方组件、子模块与消费方式。

## 1. 总原则

- **只读消费**：主工程不修改 thirdparty 任何文件；子模块上游漂移由 SHA 校验
  把关（`build-sdk.ps1` 步骤 0）
- **不编译入主树**：主树不 `add_subdirectory` 编译任何 thirdparty 源码到
  `libxcp`；A2L 栈经准备根 + IMPORTED target 消费，XCPlite 作为独立子项目
  只构建其库目标
- 路径规范：仓库内禁止写死绝对路径，全部相对路径/配置驱动

## 2. 组件一览

| 组件 | 类型 | 来源 | 用途 |
|---|---|---|---|
| `thirdparty/a2llib` | git 子模块 | `github.com/ihedvall/a2llib.git` | 上游 A2L 解析库（MIT），bison/flex 语法；由 SDK 工程封装为 `liba2l.dll` |
| `thirdparty/a2l-sdk` | 本仓库工程 | — | A2L 栈唯一构建工程（见 §3） |
| `thirdparty/XCPlite` | git 子模块 | `github.com/vectorgrp/XCPlite.git` | Vector 开源 XCP Slave，测试对手端（L3 集成与示例） |

`.gitmodules` 登记前两个子模块。

## 3. `a2l-sdk`（A2L 栈构建工程）

一个工程一次构建，产出主树消费的全部产物：

- `liba2l.dll` / `liba2l.lib` — a2llib 的 DLL 封装（上游 a2l 与全部 Boost
  静态库整体吞入，A-12）
- `libxcp_a2lbridge.lib` + `include/libxcp/a2l/*.hpp` — 语义适配层
  `a2lbridge`（C++20）
- `uchardet-shim` — 上游硬依赖的最小可链接面（子工程，预置 `uchardet_FOUND`
  + ALIAS 目标使上游跳过 `find_package`）

注意：SDK 工程 `CMAKE_CXX_STANDARD 23`（上游要求），桥接层与主树保持 C++20，
仅通过 `liba2l::liba2l` 目标接触 C++23 DLL。

构建入口：

```powershell
pwsh -File thirdparty/a2l-sdk/build-sdk.ps1 -BoostRoot <boost前缀> \
     -Config Release -OutRoot build/liba2l-prepared
```

步骤：校验 a2llib 子模块 SHA → 配置+构建 `liba2l_sdk`（串行）→ 拷贝产物到
准备根 `<OutRoot>/msvc-x64-<cfg>/`。

## 4. XCPlite（测试对手端）

- 由 `LIBXCP_BUILD_XCPLITE_SLAVE=ON` 触发 `add_subdirectory`；通过其公开
  CMake 变量（CMP0077 正常变量）关闭 examples/tests/tools/install 等，
  **不改其任何源文件**
- 载体：`tests/xcp_test_slave/`（独立 Slave 进程）与
  `tests/xcplite_*_test.cpp`（L3 集成）
- 调试指南：`docs/XCPlite_对手端协议调试指南.md`

## 5. 边界纪律（CI 门禁）

- 桥接层 `thirdparty/a2l-sdk/a2lbridge` 禁止 `#include <a2l/...>`
  （只允许 `liba2l/liba2l_api.hpp`），上游头只允许出现在 SDK 导出层
- `libxcp` 主库禁止依赖 `libxcp::a2lbridge`（对等库，依赖方向只能是
  桥接层 → libxcp）
- 由 ctest `A2lIsolation`（`tests/a2l_isolation_check.cmake`）持续校验，
  命中即非零退出
