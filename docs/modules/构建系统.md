# 构建系统（Build）

> 归属：根 `CMakeLists.txt`、`tests/CMakeLists.txt`、`examples/CMakeLists.txt`、
> `thirdparty/a2l-sdk/`
> 本文档描述 libxcp 的 CMake 构建结构、目标、开关与产物。

## 1. 工程概况

- `project(libxcp VERSION 1.3.0 LANGUAGES CXX)`，CMake ≥ 3.24，C++20
  （`CMAKE_CXX_STANDARD_REQUIRED ON`，关闭扩展）
- 编译告警：MSVC `/utf-8 /W4`（UTF-8 源字符集，避免中文注释解析异常），
  其他 `-Wall -Wextra`
- 生成器：Windows 未显式指定时强制 `Visual Studio 17 2022`（x64）；
  可命令行覆盖（如 `-G Ninja`，需先加载 vcvars64）
- 默认构建类型：未指定时按行为良好地设为 Release（缓存变量，不覆盖用户输入）

## 2. 构建目标

| 目标 | 类型 | 说明 |
|---|---|---|
| `libxcp`（别名 `libxcp::libxcp`） | STATIC | 核心库，产物名 `xcp`（`libxcp.lib`/`liba`），`POSITION_INDEPENDENT_CODE ON`；PUBLIC 依赖 `Threads::Threads` + Windows `ws2_32` |
| `libxcp_measurement_adapter` | STATIC | A2L 测量适配器（必编组件，随主工程无条件构建），链接 `libxcp::libxcp` + `libxcp::a2lbridge` |
| `libxcp_tests` | EXECUTABLE | GoogleTest 单元/集成测试（`LIBXCP_BUILD_TESTS=ON`，默认 ON） |
| `xcp_test_slave` / `XcpliteIntegration` | EXECUTABLE | XCPlite Slave 进程与 L3 集成测试（`LIBXCP_BUILD_XCPLITE_SLAVE=ON`） |
| `A2lSmoke` / `A2lGolden` / `A2lE2E` / `MeasurementAdapterTest` | EXECUTABLE | A2L 专项测试（A2L 栈必编，随 `LIBXCP_BUILD_TESTS=ON` 默认可用） |
| 示例 `xcp_master_udp` / `measurement_demo` | EXECUTABLE | 交付示例（`LIBXCP_BUILD_EXAMPLES=ON`） |

`target_sources(libxcp PRIVATE ...)` 覆盖 `src/` 全部 15 个实现文件
（协议核心 10 + `src/daq/` 3 + `src/measurement/` 2）。

## 3. 安装规则

```cmake
install(TARGETS libxcp ARCHIVE DESTINATION ${CMAKE_INSTALL_LIBDIR})
install(DIRECTORY include/libxcp DESTINATION ${CMAKE_INSTALL_INCLUDEDIR})
```

即产物库 + 公开头树；执行 `cmake --install <build-dir>`。

## 4. 构建开关（3 个，前 1 个默认 ON）

| 开关 | 默认 | 作用与约束 |
|---|---|---|
| `LIBXCP_BUILD_TESTS` | **ON** | `enable_testing()` + `tests/` 子目录 |
| `LIBXCP_BUILD_XCPLITE_SLAVE` | OFF | `add_subdirectory(thirdparty/XCPlite)` 仅建库目标（关掉其 examples/tests/tools/install 等全部开关），不修改 XCPlite 任何源文件；`LIBXCP_BUILD_EXAMPLES=ON` 时自动跟随置 ON |
| `LIBXCP_BUILD_EXAMPLES` | OFF | `examples/` 子目录；开启即自动打开 `LIBXCP_BUILD_XCPLITE_SLAVE`（根 CMakeLists.txt 判定块 FORCE 写缓存，configure 输出 STATUS 提示），无需手工同开两门 |

A2L 栈（`thirdparty/a2l-sdk` → `liba2l` / `libxcp::a2lbridge` /
`libxcp_measurement_adapter`）**不再是开关项**：随主工程无条件构建。由此
Boost（CONFIG 包，组件 locale/filesystem/process）成为 configure 期硬依赖，
自动发现顺序：显式 `-DBoost_DIR` > `C:\boost\lib\cmake\Boost-*`（取最新）>
`BOOST_ROOT` 环境变量；找不到 FATAL_ERROR 给出指引。查找走
`NO_CMAKE_ENVIRONMENT_PATH`，避免 vcpkg 全局集成劫持（其发行版缺 locale/process）。

## 5. 离线依赖

- GoogleTest：FetchContent 在线拉取；若本机 git SSL 后端无法取得凭据句柄，
  可预置 `.deps-cache/googletest/`（v1.15.2 源码），存在时自动
  `FETCHCONTENT_SOURCE_DIR_GOOGLETEST` 改用本地源
- A2L：`thirdparty/a2l-sdk` 经 `add_subdirectory` 随主树直接编译（必编组件）；
  `build-sdk.ps1` 保留为独立 SDK 开发入口（产出预构建准备根的场景），
  不再是主树前置步骤。Boost 需本机可用（见 §4 自动发现顺序）

## 6. 已知构建注意事项

- 本机（CMake 4.0 + VS 生成器）下 `cmake --build -j N` 偶发在 MSBuild 并行
  解析项目引用阶段失败于 gtest → `ZERO_CHECK`（报"0 个错误"但退出码非 0）；
  去掉 `-j` 串行构建即稳定，产物本身不受影响
- `build-sdk.ps1` 同理采用串行 `cmake --build`
- Ninja 生成器在受限沙箱下会挂起（ninja 派生子进程的管道被阻断）
- MSBuild 在同时存在 `HTTP_PROXY`/`http_proxy` 大小写重复环境变量时抛
  ArgumentException（MSB6001），`build-sdk.ps1` 已用清代理子进程封装规避

## 7. 清理

```bash
cmake --build cmake-build-release --target clean   # release
cmake --build cmake-build-debug --target clean     # debug
```

完整编译前建议先运行一次清理。
